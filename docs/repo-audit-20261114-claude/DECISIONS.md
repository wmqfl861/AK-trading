**J33 K45 的分钟部分：用“收盘后不到一分钟可用”的情景口径。**
r2 的分钟线一律是收盘后 60 秒可用。按生产规则，交易节内没有任何一个时刻能做出可用的特征快照（REVIEW 的 Z23，探针 `minute_anchor_availability_probe.py`）。照现在的设计，K45 的分钟部分没有样本。

1. K45 的分钟部分，把可用的分钟线（质量 `READY`、时间依据 `reconstructed`）的可用时刻按“收盘后 N 秒”处理。N 是 1 到 59 之间的一个固定整数，建议 5。日线、降级的行、日历、交易规则都不动。
2. 怎么实现由计划作者定，两种都可以：在研究工具里按统一规则改写内存中的可用时刻（不改 r1、r2 的任何文件）；或者重建输入。两种都要在 `CHECK.json` 里写明原来的规则、情景规则、涉及的行数。
3. 特征、预测请求、标签成熟用同一个口径。取样规则、日期、期限都不变。
4. 结果仍标 `SCENARIO / NOT_ASSESSED`。报告第一屏要有一句：“假设分钟线在收盘后 N 秒可用。”
5. 以后重建任何分钟线研究输入时，可用时刻必须早于下一格收盘，否则分钟模式不会有任何节内决策。这一条在恢复分钟线工程、准备正式输入时落实。

这不改产品规则，也不放宽任何门槛。60 秒是重建输入时定的假设，不是观测到的事实；换成 5 秒同样是假设，所以结果只能标情景。

**J34 K45 只拟合方向任务。**
生产拟合函数每个期限拟合 23 类任务，K45 的判定只用其中的方向任务。全部拟合比只拟合方向贵约 60 到 70 倍，在基准机器上很可能超过 72 小时（REVIEW 的 Z24，探针 `k45_fit_cost_probe.py`）。

1. K45-R001 只拟合方向任务：两个模式、8 个期限。
2. 从设计里去掉：§6 最后一段的其他任务附表；“公开预测可发布性”的比例（只有方向模型的模型集本来就发布不了完整预测）。
3. 保留：主表、可靠性表、“上涨概率减下跌概率”的分位数、“中性概率最大”的占比、算法表。算法表只列方向任务，但要列出四个候选算法各自在训练段内层验证上的损失。
4. 怎么做到由计划作者定：给拟合入口加一个可选参数（改产品代码，走独立硬审）；或者在研究工具里编排已有的函数（不改产品代码）。
5. 无论哪种，都要有一项测试：在合成数据上，这样得到的方向模型（选中的算法、参数、温度）与全部任务一起拟合时逐位相同。探针 `direction_only_equivalence_probe.py` 已经在生产函数上核对过一次，可以当作这项测试的起点。
6. 生产函数在拟合之后有一步“生成校准证据”，需要全部任务的模型，只有方向模型时会报错。这一步怎么处理，由计划作者在修订里写明。
7. 只含方向任务的模型集只在这个研究工具里使用，不进入决策管线，不用于发布预测。

**J36 K45 的负结论怎么说：先看检验分辨得了多少。**
日线部分的检验段只有约 70 个可用交易日。这个长度下，模型即使真有一两个百分点的技能，也很可能看不出来。设计里“没有显示出信息量”这句固定结论，用在这种单元上说过头了。

1. 每个单元多报一列：Brier 技能普通 95% 区间的半宽。
2. 半宽不超过 0.02（技能的 2 个百分点）的单元，算“分辨得了”。
3. 一个模式里没有任何单元达到继续条件时：至少有一个“分辨得了”的单元，才写“没有显示出信息量”；一个都没有，写“这次检验分辨不了”。
4. 两个模式都适用。设计里其余的判定顺序不变。
5. 0.02 这个数请计划作者在修订里确认或调整，但必须在看到任何检验段结果之前写死。
