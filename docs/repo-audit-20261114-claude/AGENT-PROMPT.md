# 给本地 agent 的提示词（第七轮，第四批）

用法：把下面代码块里的全文发给本地 agent（Root）。

这一份没有留待填的空。它替你定下的事都写在 [DECISIONS.md](DECISIONS.md) 里，最要紧的五件是：

- 三个日线规则到此为止，不再调参数。六个品种看下来没有稳定的优势。再出一份你能直接读懂的第二版报告，然后收尾。
- v2 的预测检验（K45）这一批真的跑一次。跑之前改三处设计：分钟数据按“收盘后几秒可用”的假设处理（建议 5 秒）；只拟合方向这一类任务；正式跑之前先预演一遍。前两处不改的话，这次检验会白跑。
- 检验用的那段数据只看一次。独立审核通过之后才看。
- v2 分钟线的工程项继续暂停。检验结果出来之后怎么走，已经按四种可能的结果写定。
- 分工不变。

你不同意哪一条，发之前改掉提示词里对应的那一行就行。

```text
本批任务：按第七轮外部审核的文档完成第四批。完成或被阻塞后停止，不自动开始下一批。

一、先取得文档并核实

1. git fetch origin，把分支 claude/repo-audit-20261114 合入 main。它只新增 docs/repo-audit-20261114-claude/ 目录。记录合入后的 HEAD。

3. REVIEW.md 是外部审核意见，不是产品硬审核。DECISIONS.md 是我认可的决定，见第二节。涉及代码语义的地方仍由计划作者裁定；裁定和外部文档不一致时以裁定为准，把差异写进状态页。
4. 动手之前，在本机跑 REVIEW.md 附录里标了“请复现”的五条命令，把每条的原始退出码和结果写进 docs/CURRENT-STATUS.md。结果和文档不一致的地方，以你的实测为准，并写明差异。其中 minute_anchor_availability_probe.py 在本机的退出码如果是 0（延迟 60 秒时交易节内也有可用快照），先不做 K45a 里关于可用时刻的那一项，把输出写进状态页。

二、我的决定

- 本批采纳 DECISIONS.md 的 J32–J42。此前 J1–J31 现在的状态，以它的第二节为准。其中：
  · v1 的三个日线规则到此为止：参数和写法不再动，不做闸门对照和参数检验。出完六品种报告第二版（K46）就收尾。
  · K45 的分钟部分，可用的分钟线按“收盘后 N 秒可用”的情景口径处理，N 是 1 到 59 之间的固定整数，建议 5。不改 r1、r2 的任何文件。怎么实现由计划作者定。
  · K45 只拟合方向任务。怎么做到由计划作者定；无论哪种做法，都要有测试证明方向模型与全部任务一起拟合时逐位相同。
  · K45 用 r1 还是 r2，由计划作者只凭元数据核对规则可见性之后写定。同意把 K42b 的严格适配用到 K45；正式读取入口不改。
  · K45 的负结论按 J36：每个单元加报区间半宽，分辨不了的写“这次检验分辨不了”。
  · K45 分三个阶段，检验段只碰一次：阶段一出漏斗表；阶段二冻结并预演；独立硬审无条件 PASS 之后才做阶段三。
  · v2 分钟线的工程项继续暂停。R001 之后怎么走按 J38 的表，不临时改。
  · K14 的三处遗留本批不单独处理；只有计划作者为 K45 选择修改拟合入口时，才把读回模型集的哈希一并修掉。
  · 报告和清单的入库规则按 J40。
  · 鉴权测试按 J41 换一种装法再试一次，装不起来就关闭这一项。

- DECISIONS.md 没有覆盖、又确实需要我决定的新事项：记进状态页“待决”一栏，继续做不受影响的工作，不要因此停下整批。
- 下列事项不适用默认值，必须有我本人的明确指示：开启真实交易或发出任何真实报单、撤单；读取、打印、修改凭据；消耗最终 holdout；仓库可见性、令牌、防火墙、服务、数据库角色、系统设置、交易客户端界面的实际操作；删除输入数据、合同锁、验收清单、审核结论或失败记录；向仓库以外发布代码或研究结论。

三、本批任务

范围、做法、交付物和验收都在 NEXT-BATCH.md 第二到第五节，按那里的顺序和分线执行：

计划作者
1. K45a：在 K45 设计文件末尾追加“修订 v2（实施前）”，写定 NEXT-BATCH.md 第三节表里的七项。修订入库之前不写 K45 的工具。

关键线（一条开发，一条独立审核）
2. K45b：K45 的工具和合成测试；阶段一（漏斗表、耗时表）；阶段二（拟合、对照、定温度、冻结、预演）；独立硬审。
3. K45c：独立硬审无条件 PASS 之后做阶段三：检验段评分一次，编号 K45-R001，结果报告入库。

支撑线
4. K46：六品种报告第二版。只读已有的逐日结果，不新跑回放。第一屏按 NEXT-BATCH.md 给的写法。
5. S4b：鉴权测试再试一次。

K45a、K46、S4b 可以同时开始。

四、要求

- 涉及语义的地方先有计划作者的裁定，不自行决定。
- K45 的阶段一和阶段二不读检验段的标签和价格变动。阶段三之前，任何人不看检验段的标签、价格变动或由它们算出的数。
- 阶段一遇到 NEXT-BATCH.md 写的停止点，按表处理。不为了多出样本而改日期、取样、期限或门槛。
- 如果本批改了产品代码：改动前后各有一次全量，按用例比较，新增失败必须为 0。
- 不为了让测试通过而修改预期、刷新冻结哈希、添加 skip 或 xfail、放宽门槛。
- 完成标准：独立硬审无条件 PASS、合入 main、CI 通过、全量无新增失败。新增的测试文件随同一次提交加进 CI 的清单。
- K46 的报告和 K45-R001 的主表都要有独立复算，逐格相同。
- 报告是写给我看的：第一屏不超过五句日常语言加一张表；金额取整、带千分位；正文里的表不超过 50 行；结论只写事实，不写交易建议。
- CHECK.json 里登记的工具、配置、测试文件哈希必须等于同一次提交里的文件；仓库外文件的清单只入库哈希和文件数。
- 每项完成即提交并推送 main。提交说明写清改动、命令、原始退出码、passed/failed 数和全量对照结果。不为每一步新建过程文档。

五、本批不做

- 不改三个 v1 规则的参数和写法，不做闸门对照、参数检验、连续主力回放。
- 不恢复暂停的各项：合同锁分级的实施、T7 夹具重新冻结、H5′、K04b、K11、K13、K41。
- K45 不拟合方向以外的任务，不经过 M5 的正式实验入口，不登记或动用最终留出集。
- 不改“明确方向”的定义和任何准入条件。
- 不改统计门槛、风控参数、窗口长度，不放宽 synthetic=false 的日历门槛。
- 不改 r1、r2 的任何文件，不修填真实输入里缺失的规则字段，不导出新的行情数据。
- 不处置 K25 表里除鉴权测试之外的文件。
- 不新增 src/ 下的包或子系统。不用 numpy。
- 不删除已入库的 CHECK.json。
- 不续接 N8、DISPATCH，不做完整 shadow、Forward 采集、本地 paper。
- 不修改 docs/repo-audit-*-claude/ 下任何外部审核文件的内容。
- 规则文件本批不改。

六、边界

- 不读取、不打印、不修改 .env 和任何凭据。
- 仓库可见性、令牌、防火墙、服务重启、数据库角色、Windows 系统设置、交易客户端界面只由我本人操作，你只准备步骤。

七、状态与收尾

- 状态只更新 docs/CURRENT-STATUS.md。页首三行给我看，每行不超过 40 个字：本周能看到什么；卡在哪；需要我做什么。第三行列出 DECISIONS.md 第四节里我还没做的事，不要写“暂无”。

- 本批全部完成或被阻塞时停止，给我一页摘要，包含：
  1. K45-R001 的第一屏和主表，直接贴出来；如果停在了阶段一或阶段二，贴漏斗表和停下的原因；
  2. K46 的第一屏、总表和合并口径的表，直接贴出来；

  7. S4b 的结果；
  8. 计划作者各项裁定的摘要，以及与外部文档的差异；
  9. 本批全量基线的通过、失败、错误数，以及前后的对照；没有改产品代码就写明没有改；
  10. 状态页“待决”一栏的全部内容。
```
