### 工程与流程

**J26 `.gitattributes`：按下面的办法完成。**
目标是两条：`.gitattributes`（一行 `* -text`，以 LF 换行）入库；工作区里每个已跟踪的文件与仓库里的内容逐字节相同。做法可以由 Root 调整，下面是一种可行的顺序：

1. `git ls-files --eol` 列出索引是 `i/lf`、工作区是 `w/crlf` 的文件（以及反过来的，如果有）。把文件数写进状态页。
2. 逐个确认它们“只差换行”：工作区的字节把 `\r\n` 换成 `\n` 之后，与 `git cat-file blob HEAD:<路径>` 逐字节相同。有任何一个不满足，说明它有真实的本地修改：停下这一项，列出文件。
3. 新增 `.gitattributes`，只提交这一个文件。
4. 对第 1 步列出的每个文件：先删除工作区里的这个文件，再 `git checkout -- <路径>`。Git 认为文件没有变化时不会重写它，所以要先删。文件内容以仓库为准，不会丢失。
5. `git update-index --really-refresh` 之后，`git status --porcelain` 应为空。再对全部已跟踪文件核对一次“工作区字节等于 HEAD 字节”，把不一致的文件数写进状态页，应为 0。

第 4 步会把合入的外部审核文件从 CRLF 写回 LF。这是恢复到已提交的内容，不算修改外部审核文件。不改 `core.autocrlf`，不做 `git add --renormalize`，不改任何文件在仓库里的内容。
