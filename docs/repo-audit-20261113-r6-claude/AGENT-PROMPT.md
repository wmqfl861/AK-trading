# 给本地 agent 的提示词（第六轮，第三批）

用法：把下面代码块里的全文发给本地 agent（Root）。

这一份没有留待填的空。它替你定下的事都写在 [DECISIONS.md](DECISIONS.md) 里，最要紧的五件是：

- 三个日线规则先不调参数。下一步补两个口径：只看主力合约，和另外五个品种（原油、豆粕、PTA、沪深 300 股指、工业硅）。
- 留出集定为 2026-09-05 及之后的行情。现有三份数据整包当研究数据用。
- 授权本地 agent 用现有的只读脚本，从你的行情库再导出五个品种的日线。脚本自己读连接配置，agent 不看、不改。
- v2 分钟线的工程项暂停。先设计一次便宜的检验：v2 的预测在真实数据上有没有信息量。这一批只写设计。
- 分工不变。

你不同意哪一条，发之前改掉提示词里对应的那一行就行。

```text

1. git fetch origin，把分支 claude/repo-audit-20261113-r6 合入 main。它只新增 docs/repo-audit-20261113-r6-claude/ 目录。记录合入后的 HEAD。

4. 动手之前，在本机跑 REVIEW.md 附录里标了“请复现”的四条命令，把每条的原始退出码和结果写进 docs/CURRENT-STATUS.md。结果和文档不一致的地方，以你的实测为准，并写明差异。

二、我的决定

- 本批采纳 DECISIONS.md 的 J19–J31。此前 J1–J18 现在的状态，以它的第二节为准。其中：

  · 日历或规则证据未核实的真实输入，可以用于测量和描述性报告，结果一律标 SCENARIO / NOT_ASSESSED。synthetic=false 的日历门槛不变。
  · 授权用 scripts/export_futures_input.py 从本机行情库只读导出五个品种的日线。脚本通过 --env-file 自己读连接串；你不查看、不打印、不改动那个文件的内容，不新建或修改数据库角色。

  · 行情服务的鉴权测试在一个独立的虚拟环境里跑一次，不改动基准环境。
- DECISIONS.md 没有覆盖、又确实需要我决定的新事项：记进状态页“待决”一栏，继续做不受影响的工作，不要因此停下整批。

三、本批任务

范围、做法、交付物和验收都在 NEXT-BATCH.md 第二到第五节，按那里的顺序和分线执行：

关键线（一条开发，一条独立审核）
1. K43：螺纹钢的主力口径。只读已有的逐日结果重新归集，不新跑回放。
2. K44：另外五个品种，规则、参数、成本口径与螺纹钢相同，全部合约和主力两种口径。先由计划作者写短计划。

支撑线
3. S3：.gitattributes；规则文件按 DECISIONS.md 第五节做两处替换；CI 的测试清单加三个文件。先做这一项。
4. K14：预测路径上三处随训练样本量增长的开销，改成结果逐位相同的写法。这是本批唯一改产品代码的一项，写集和缓存的有效性保证请计划作者确认，走独立硬审。K14 开工前的那次全量同时作为本批的起点基线。
5. K42b：把 r2 就绪清单里标 NA 的格子量出来。只统计数量、质量状态和时间戳，不计算价格变动或标签。
6. S4：行情服务的鉴权测试跑一次，结果写进状态页。

计划作者
7. K45：预测信息量检验的设计。只写设计，不实施；设计定稿之前不看检验段的价格变动和标签。

S3 和 K43 可以同时开始。

四、要求

- 涉及语义的地方先有计划作者的裁定，不自行决定。
- K14：改动前后各有一次全量，按用例比较，新增失败必须为 0；结果必须逐位相同，做不到就停下这一项。
- 不为了让测试通过而修改预期、刷新冻结哈希、添加 skip 或 xfail、放宽门槛。
- 完成标准：独立硬审无条件 PASS、合入 main、CI 通过、全量无新增失败。新增的测试文件随同一次提交加进 CI 的清单。
- K43、K44 的报告要有独立复算：审核者从同一批源文件独立重算，表格逐格相同；K44 的矩阵由审核者独立再跑一遍，产物逐字节相同。
- K42b、S4 交付的是表格和记录，不需要独立硬审，但都附上产生它的命令和原始退出码。
- 报告是写给我看的，写法按 DECISIONS.md 的 J31：第一屏不超过五句日常语言加一张总表；内部标记只放在表头、脚注和 CHECK.json 里；结论只写事实，不写交易建议。
- 每项完成即提交并推送 main。提交说明写清改动、命令、原始退出码、passed/failed 数和全量对照结果。不为每一步新建过程文档。

五、本批不做

- 不改三个 v1 规则的参数和写法，不做“去掉行情状态闸门”的对照。
- 不实施 K45，不拟合任何真实数据上的 v2 模型。
- 不恢复暂停的各项：合同锁分级的实施、T7 夹具重新冻结、H5′、K04b、K11、K13、K41；不做原规格的 K12。
- 不改“明确方向”的定义和任何准入条件。
- 不改统计门槛、风控参数、窗口长度，不放宽 synthetic=false 的日历门槛，不登记或动用留出集。
- 不处置 K25 表里除鉴权测试之外的文件。

- 不修改 docs/repo-audit-*-claude/ 下任何外部审核文件的内容。
- 不做全库换行规范化或格式化。

六、边界

- 不读取、不打印、不修改 .env 和任何凭据。K44 的导出按 DECISIONS.md 的 J23 做：连接串由脚本自己读取，你只把文件路径传给它。

- 遇到 NEXT-BATCH.md 第七节列出的任一停止条件，停下对应任务并写进状态页，其余任务继续。

七、状态与收尾

- 状态只更新 docs/CURRENT-STATUS.md。页首三行给我看，每行不超过 40 个字：本周能看到什么；卡在哪；需要我做什么。第三行列出 DECISIONS.md 第四节里我还没做的事，不要写“暂无”。

- 本批全部完成或被阻塞时停止，给我一页摘要，包含：
  1. 六个品种的总表和第一屏的几句话，直接贴出来；

  3. 各任务的状态、合入的提交号、阻塞原因；

  8. 全量基线的通过、失败、错误数，以及本批前后的对照；
  9. 状态页“待决”一栏的全部内容。
```
