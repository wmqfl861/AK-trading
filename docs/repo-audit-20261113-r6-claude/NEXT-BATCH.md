## 三、关键线

### K43 螺纹钢的主力口径

**目标**：回答“只在当时的主力合约上做，每年是多少”。现在的合计是 84 个互相重叠的账户之和（REVIEW 的 Z14）。

**输入**（只读，都已通过独立审核）：K40-A 用的三个规则的逐日结果；K40-B 矩阵里 100 万元、基准情景下两个对照的逐日结果；`real-input-02` 的日线（取持仓量）。

**口径**：

- 每个交易日的主力合约：当天有 K 线的合约里，上一根 K 线收盘持仓量最大的那个。只用当天开盘前已经知道的信息。并列、持仓量缺失、样本第一天怎么处理，由计划作者定并写进报告。
- 主力口径当天的净额：主力合约那个账户当天的净额变化。
- 这是把已有结果重新归集，不是一次可执行的回放：没有换月成本；主力切换时，仓位状态直接换成新合约账户当时的状态。这两点写进报告的限制里。

**交付**（螺纹钢报告新增一节，加对应的 CSV）：

- 五种做法（三个规则、买入持有、始终空仓）各一行：全期净额、分年净额、为正的年数、最差的年份和金额、最大回撤（累计净额从峰值到谷值，元）、最长回撤持续的交易日数。
- 主力切换的次数；有主力合约的交易日数占全部交易日数的比例。
- 一张对照：主力口径的全期净额，对比全部合约口径下平均每个账户的净额。

**验收**：独立审核者从同一批源文件独立重算，表格逐格相同；各年净额之和等于全期净额；每个交易日至多归到一个合约；`CHECK.json` 里这一节 `new_simulation=false`。

K43 入库后开始。先由计划作者写一份短计划，定三件事：现有的敏感性工具怎样用到别的品种上；每个品种的经济参数从哪里取；导出的输入怎样冻结和核对。

| 项目 | 内容 |
| --- | --- |
| 品种 | `FIXED_UNIVERSE` 里螺纹钢之外的五个：INE.SC、DCE.M、CZCE.TA、CFFEX.IF、GFEX.SI |
| 数据 | 用 `scripts/export_futures_input.py` 导出日线，2020-07-20 至 2026-09-04，授权见 DECISIONS 的 J23 |
| 合约乘数、最小变动价位 | 取导出工具所用品种目录里的值；目录里没有的，由计划作者查交易所合约规格，在报告里注明来源 |
| 手续费、滑点、保证金 | 与螺纹钢相同的假设：成交金额的万分之一加每手 0.01 元；每次成交 1 个最小变动价位；保证金 12%，占用不超过权益的四成 |
| 矩阵 | 与 K40-B 相同：五种做法 × 四档资金 × 四种成本情景 |
| 口径 | 全部合约，和主力（同 K43） |
| 规则与参数 | 不变 |

**交付**：

- `docs/research/v1-daily-baseline-universe.md`：六个品种的总报告，写法按 DECISIONS 的 J31。螺纹钢沿用已入库的结果，不重跑。

**验收**：同 K40-B。独立审核者独立跑一遍矩阵，产物逐字节相同；独立复算逐格相同；`new_simulation=true`、`holdout_read=false`；每份输入的最后一根 K 线不晚于 2026-09-04。

### K14 三处随训练样本量增长的开销

**为什么**：REVIEW 的 Z13。

**建议写集**（由计划作者确认）：`src/ak_trading/v2/probability/models.py` 和对应的测试。缓存如果放在别的模块，由计划作者定。

**做法**（结果必须逐位相同）：

1. `_apply_empirical_cdf`：同一个模型、同一个层级的累计计数只算一次，单次预测的耗时不再随样本数增长。
2. `_apply_empirical_quantile`：样本只转换一次。
3. `ForecastModelSet.content_hash`：同一个没有改动的对象只算一次。
4. 请计划作者裁定：模型集是冻结的数据类，但里面每个模型是普通字典。缓存怎样保证不会返回过期的结果，是按身份加内容校验、在构造时冻结，还是别的办法。

**验收**：

1. M1–M4 的冻结预期原样通过；同一段回放改动前后的产物逐字节相同；模型集的哈希值不变。
2. [probes/empirical_apply_scaling_bench.py](probes/empirical_apply_scaling_bench.py) 的退出码由 1 变为 0。如果实现改掉了探针用到的私有函数名，探针跑不起来，就由审核者按同样的办法另写一个等价的测量。
3. 新测试覆盖两件事：新旧实现在随机样本上逐位相等（包括负值、零、超出期限的值、首选层级为空时的回退）；模型内容被改写之后，不返回旧结果。
4. 全量对照无新增失败；独立硬审无条件 PASS。
5. [probes/context_cost_profile.py](probes/context_cost_profile.py) 改动前后各跑一次，两次的输出写进状态页。

不用 numpy（J4）。

### K45 预测信息量检验的设计

本批只写设计，不实施。检验段的价格变动和标签在设计定稿之前不看；K02b 已经公布过分年的标签占比，这一点在设计里写明。下一轮我审核设计，之后再定是否实施。

**要回答的问题**：v2 的方向预测模型在真实数据上拟合之后，对没有见过的时段，是否比“只报历史占比”预测得更准。

**设计要写定的内容**：

| 项目 | 要求 |
| --- | --- |
| 数据 | 分钟线用 r2。日线有两个选择：r2 里的日线，或 v1 的 `real-input-02`（时间长得多，但不是 v2 的输入格式）。选哪个、后者怎样在不改产品语义的前提下变成 v2 能读的情景输入，由设计回答 |
| 切分 | 按时间先后分成训练、校准、检验三段，互不重叠，段间按生产规则留间隔。起止日期在设计里写死 |
| 对象 | 方向预测，两种模式各自的全部期限。其余任务（路径、分位数、时间）列为附表 |
| 对照 | 同一训练段上的无条件占比模型，即生产代码里的 unconditional 候选 |
| 指标 | 检验段上的多分类 Brier 分数和对数损失；技能 = 1 − 模型损失 ÷ 对照损失；按交易日分块的自助法给 95% 区间；可靠性表 |
| 附带输出 | 上涨概率减下跌概率的分位数；中性概率最大的占比（J22 需要）；每个任务被选中的算法各占多少 |
| 判定规则 | 预先写定。建议：某个模式、某个期限的技能区间下限大于 0，这个模式值得继续；所有期限的区间都包含 0 或更低，结论是“现有特征和模型在这份数据上没有显示出信息量”，下一步回到特征和模型，不是策略层 |
| 一次性 | 检验段只评估一次。之后改了特征或模型再评估的，都要编号，并和之前各次一起报告 |
| 抽样 | 如果分钟线全量太慢，抽样办法（例如每隔若干分钟取一个决策时刻）要在看任何结果之前写定 |
| 工程约束 | 只调用生产函数（特征、预测请求、标签、拟合、校准、预测），不改产品语义；工具放在 `tools/experiments/`；不经过 M5 的正式实验入口，不登记留出集；结果标 `SCENARIO / NOT_ASSESSED`；输出不含行情明细 |
| 估算 | K14 合入后的运行时间（用 K42b 的样本量）；需要新写多少代码；已知的阻塞 |

交付：`docs/research/k45-forecast-skill-design.md`。
