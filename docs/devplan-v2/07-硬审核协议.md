# 独立硬审核协议

协议版本：`hard-review-v2.1.0`。本协议用于后续M1—M5代码实施验收；当前文档编制阶段只做静态阅读与一致性检查，**不运行测试、不出具代码实施PASS**。

## 1. 审核对象与独立性

每次审核固定为一个节点、一个不可变提交/文件哈希集合、一个契约lock版本和一份开发文档版本。审核者必须是未参与该节点实现的独立子代理；原开发者自检不能代替独立审核。审核者只读实现、文档和冻结输入，在独立新审核产物目录写证据，不能一边修代码一边判自己通过。

依用户对本轮 v2.1 的显式授权，全部外部 Codex 调用统一使用 `gpt-6-astra` / reasoning effort `max`，并经 watchdog wrapper 调用；ZCode-native Agent 工具没有 `model` 字段，必须如实记录其模型不可由该工具指定，不得伪称已设置；本句仅校正审核模型要求，不降低审核标准，也不授权修改任何已有 agent 配置。其他agent保留各自已授权配置，不为了审核更改baseURL/API key/model/provider/context/compression。审核者必须得到完整任务边界，不能继承开发者口头声称“都通过了”作为证据。

实现者可以查看所有节点文档，但只能修改自己独占文件。审核者发现问题只报告FAIL和证据，由原节点修复；公共契约有问题走M1变更控制，不允许审核者直接改消费者让测试过。

## 2. 审核输入包

主集成者交付以下具体材料后才启动审核，不以聊天摘要代替：

1. 本目录总纲、被审核节点完整文档、M1契约、已确认 `docs/probability-strategy-v2-plan.md`，以及本协议。
2. 开发前的文件基线与提交标识，开发后的精确文件列表/哈希；仓库存在大量未跟踪文件时必须有逐文件哈希基线，`git diff`为空不是零改动证明。
3. 节点所有权白名单、公共contract-lock.json、依赖节点的PASS报告和对应hash。
4. 开发者测试记录：命令、工作目录、Python版本、开始/结束时刻、返回码、pass/fail/skip/deselected计数、stdout/stderr原文及sha256。
5. 对应冻结输入/配置/代码/模型/标签/成本/随机种子及输出manifest；数据标记为SYNTHETIC、HISTORICAL_RECONSTRUCTED、HISTORICAL_PIT或FORWARD_SHADOW。
6. 实际验收范围与已知不足；M5另交最终留出消费登记、真实影子源日志与固定cohort成熟证据。

任何缺项先FAIL，不能用“开发者说有”替代；资料补齐后再审核。依赖节点只有工程PASS时，统计失败仍应通过NO_TRADE传播，不伪装为已验证交易资格。

## 3. 审核步骤

### R1：读规格并固定范围

完整读节点文档和M1契约，建立 `requirement_id → 文件/符号/schema/测试/产物证据` 对照。核对根目录为 `D:/Projects/AK-trading/`，先检查Python3.12及环境隔离，不打开 `.env` 或真实令牌配置。代码发现优先用现有codebase-memory图谱，结果不足可读实际文件；不能为方便修改现有代码或配置。

requirement_id使用各节点硬审核清单中固定的`M1-H01`等ID，不由审核者临时起名；本协议领域表用固定`D01`—`D11`。contract-lock.required_check_ids登记各节点全部H项及其适用D项，报告必须覆盖清单全集；文件/任务/测试清单同样逐条关联。规则改动不复用已删除ID，新要求在末尾分配新号，避免改序后旧报告被误解释。

领域ID适用映射固定：M1=`D01,D02,D07`；M2=`D02`；M3A=`D01,D02,D03,D04`；M3B=`D01,D02,D05,D06`；M4=`D01,D02,D04,D05,D06,D07,D08,D09`；M5=`D01`—`D11`全部。每项按该节点职责验证其本地实现及依赖证据，不要求M1提前实现M3B策略；M5必须核验最终完整行为，不能只凭依赖报告替代集成。

读取/枚举git状态仅作辅助，使用 `git --no-optional-locks status --short`；不要调用reset、clean、stash、checkout恢复开发前状态。不要把其他人的既有修改算成本节点变更；哈希比较以本次开发基线为准。

### R2：文件与契约硬核对

逐一核对节点独占清单，文件不存在FAIL；有新增越界文件、已有文件被修改或共同fixture被改FAIL。公共类型字段名、类型、枚举、空值规则、函数签名、因子/策略ID和版本逐字对照；不同模块私传隐藏字段、字典缺schema、重复定义不一致都FAIL。

确认M1 lock能校验公共代码/fixture/schema/signature/政策；数据或模型跨版本不允许静默兼容。新包与v1包显式区分，分钟不经过旧日线限定类型；无旧代码零改动证明不能PASS。

### R5：产物与失败闭环

独立重读JSON/CSV，核对schema、全部字段、Decimal、排序、hash、样本排除/缺失、输入版本与输出来源。对相同输入重现至少核对核心产物逐字节一致；复现不新增统计证据。M5没有真实feed或cohort成熟证据时必须保留未完成，不将SHADOW_REPLAY标成SHADOW_ACCEPTED。

FAIL写明最小复现、具体文件/符号/字段、违反条款、实际值与期望值。修复回原节点；审核者只在新的精确hash上重新出报告。依赖公共契约的修改需要新lock和消费者升级，不能在审核报告里口头豁免。

## 4. PASS / FAIL 条件

**PASS必须同时满足**：全部指定文件存在且所有权正确；契约/schema/版本逐字一致；规定测试独立重跑通过；关键手算和反例成立；无未来函数、无不实数据/成交/统计结论；全部必需运行产物完整可验证；依赖节点审核有效；本节点硬检查单每项有证据。

**任何一项不满足即FAIL**，包含无法执行测试、证据缺失、无实际用例、借由skip隐藏失败、v1改动、越界写入、未知当零、未来泄漏、马丁风险不冻结、未完成退出虚报空仓、最终留出重复调参、实时未验收冒充通过。不得给“基本PASS”“条件PASS”或把缺项改为不适用。

工程PASS与统计PASS分开。模型/策略统计失败但工程按规则关闭新增风险，可以得到节点工程PASS和statistics=FAIL/INSUFFICIENT；不能升级其交易资格。M5完整阶段需要真实影子与cohort成熟证据，缺失时node_verdict=FAIL，允许另外记录offline_engineering=PASS。实盘启用与资金始终是本协议之外的后续明确授权阶段。

M5允许先做独立的OFFLINE_STATISTICS资格审核，用M5规定qualification_review.json，不与本协议node_verdict混用。审核者独立重跑M5统计/分组/留出消费/因果及M4准入测试，重算该资格全部必需组，PASS只表示相应范围可进入无实盘影子；检查报告hash、参数源码、有效期与范围后发行StrategyQualification。缺真实20日运行日志时M5总体仍FAIL，不因资格已发行而豁免。最终留出审核只能同hash重放，不能借资格审核再选模型或门槛。

## 5. 审核产物schema

后续每次审核写 `data/research_runs/v2/audits/<node>/<revision>/review.json` 和 `review.md`，两个路径组件由审核调用者指定，目录必须新建；日志名固定为`commands.json`。本次文档任务不创建这些目录。

review.json精确结构：

```json
{
  "schema_version": "ak_probability_hard_review_v2.1.0",
  "node": "M1",
  "document_version": "devplan-v2.1.0",
  "reviewed_revision": "内容哈希或不可变提交标识",
  "contract_lock_sha256": null,
  "reviewer_id": "独立审核实例标识",
  "independent": true,
  "node_verdict": "FAIL",
  "engineering": "FAIL",
  "statistics": "INSUFFICIENT",
  "runtime": "OFFLINE_ONLY",
  "checks": [],
  "commands_sha256": "64位SHA-256",
  "source_hashes": {},
  "artifact_hashes": {},
  "blockers": []
}
```

这只是格式样例，不是本项目实际审核结论。node只能M1/M2/M3A/M3B/M4/M5；checks每项`{requirement_id:str,status:"PASS"|"FAIL",evidence_paths:list[str],observed:str,expected:str}`；blockers为string[]；contract_lock_sha256在M1首次冻结审核之前可null，其他节点必须为实际hash。M1先审核代码/契约再发布lock，lock引用审核报告hash，报告不反向引用尚未存在的lock，避免哈希循环。

commands.json根`{schema_version:"ak_probability_review_commands_v2.1.0",commands:list[object]}`；每条命令精确`{command:str,cwd:str,python_version:str,started_at:str,ended_at:str,exit_code:int,collected:int,passed:int,failed:int,skipped:int,deselected:int,stdout_path:str,stderr_path:str,stdout_sha256:str,stderr_sha256:str}`。时间是带时区ISO字符串，stdout/stderr在同一审核目录内，日志不得有凭据。

review.md中文列结论、阻断条款、关键手算、实际命令摘要、依赖hash和统计/实时不足。修复建议可以给出，但不得代替FAIL事实或降低验收阈值。

## 6. 禁止事项

- 禁止读取`.env`、真实token配置或打印数据库URL；禁止联网查证来替代冻结输入；禁止实际下单和后台任务安装。
- 禁止修改现有代码/配置/v1产物；禁止在审核中改被审核节点源码、公共契约或测试断言。
- 禁止凭开发者测试截图、旧日志或口头结论判PASS；禁止把代码可导入、工具安装成功当业务正确。
- 禁止以截断样本、删坏行、填零费用/概率、重新画区间、缩短期限或最后一根强平制造通过。
- 禁止将高胜率、econ自报信心、模型熵或抽样权重替代联合准入；禁止为了多交易降低已冻结门槛。
- 禁止将每分钟或每次加仓当独立样本、重复使用最终留出选参数、独立episode收益累计成连续复利。
- 禁止在无真实链路/规则/成交证据时宣称SHADOW_ACCEPTED、真实严格回测或已获实盘权限。
- 禁止未经用户明确授权改变任何agent模型/推理/上下文/压缩配置。
