## 1. 风险消费同一逐合约估值

**所有者：M4主责（decision/risk.py、ledger.py、replay.py、pipeline.py），M1负责003类型/lock，M5负责shadow调用。** 路径均在 `src/ak_trading/v2/` 下。
~~~python
# ak_trading.v2.decision.risk
def enforce_account_risk(proposals: tuple[StrategyProposal, ...],
                         gates: tuple[GateDecision, ...], account: AccountSnapshot,
                         instruments: tuple[Instrument, ...], states: tuple[StrategyState, ...],
                         pending_intents: tuple[OrderIntent, ...], rules: tuple[TradingRule, ...],
                         capacity_remaining: Mapping[str, int], policy: Mapping[str, JsonValue], *,
                         valuations: tuple[ValuationMark, ...]) -> tuple[GateDecision, ...]: ...
~~~
`valuations`无默认值，直接使用003的公共类型。M4在同一候选事务中用公开`ContinuousLedger.checkpoint(..., pending_remaining_lots=...)`取得风险前快照C，传`account=C.account, valuations=C.valuation_marks`；states、pending、容量也来自同一事件边界，不能混用上个checkpoint的marks与本次成交后的账户。候选快照不是落盘提交，最终提交仍按003执行；AccountSnapshot不扩字段。
校验marks按合约唯一且恰覆盖非零PositionLot合约；空仓才允许空tuple。逐批手数为正整数且非bool，与原Fill净额及strategy/episode归属守恒；层累计成交历史不等于减仓后的剩余手数。按当前剩余lots及方向计算毛占用，不按entry_price、汇总margin比例或跨合约净额分摊。无持仓的新候选使用已过数据gate的当前上下文/冻结预算，不能为其伪造持仓mark。
逐mark执行003的价格、状态、源bar、时点和价龄校验。调用方在同一C上核对`SHA256(canonical_json_bytes(encode_record(rule))) == C.rule_hashes[mark.rule_id]`；risk再核对唯一rule_id、contract_id、当时可见/有效窗口及所需乘数/方向保证金率。CURRENT还须通过当前事件的原时效/规则要求；STALE仅按003保存的旧组合展示，不能用新规则“修复”旧mark。规则同ID异内容、数量/时点错配为输入错误，原始错误留证。
任一持仓缺价、旧价、UNVALUED或规则未知时，新增风险gate为false/权重0，合并`DATA_STALE/COST_UNKNOWN`与003原因；已有REDUCE/EXIT沿原退出通道，成交未知则EXIT_PENDING/INCOMPLETE。结构损坏不得进入新事务，宿主只能基于最后已验证持仓处理退出。
**手算/反例及重跑：** A多2手、entry100、mark110、乘数10、保证金率0.1；B空3手、entry200、mark190、乘数5、空头率0.2，实际保证金=220+570=790、浮盈=200+150=350；A成交后剩1手则保证金=110+570=680。A旧mark不能按B价刷新，过期即无新风险；覆盖缺合约/重复mark/bool手数/未来bar/规则hash冲突及恢复前后相同结果。重跑R1、R4、R5。

M5报告在metrics.json根增加必填`replay_summaries:list[object]`，每项为上述对象再加`split_id:str,run_policy_sha256:str,model_bundle_sha256:str`，由实验宿主从真实调用范围补齐；没有回放时为空数组。金额/ID/状态必须与引用账本对齐，中文报告同时展示完整轮和期末账户，输出schema见§7。
**手算/反例及重跑：** 同轮多2手，乘数10，执行价101开仓、旧规则开仓费每手2；当天103平1手、旧平今费3；次交易日99平最后1手、新规则平昨费5。完整毛盈亏20−20=0，净损益=−(4+3+5)=−12。若三腿reference分别为100/104/100，滑点分解20+10+10=40，不能算成−52。第二次平仓前mark100时，成熟轮数0、该未闭合轮已实现净额13、浮亏−10、账户增量3。覆盖旧规则缺失/未来版本替换、未提交尾Fill、同ID冲突、跨段祖先缺失；重跑R4、R5。

## 3. 生产者公开最终内容hash

**所有者：M2（seasonality.py）、M3A（probability/models.py、regimes.py）、M4（decision/payoffs.py、pipeline.py）分别实现，M5共用，M1冻结签名。**
~~~python
# 以下方法分别定义在原类型，不添加序列化字段：
# ak_trading.v2.probability.models.ForecastModelSet
# ak_trading.v2.probability.regimes.RegimeReference
# ak_trading.v2.seasonality.SeasonalityModel
# ak_trading.v2.decision.payoffs.PathPayoffModel
def content_hash(self) -> str: ...

# ak_trading.v2.decision.pipeline
def model_hashes_for(forecast_models: ForecastModelSet, payoff_model: PathPayoffModel,
                     regime_reference: RegimeReference,
                     seasonality_model: SeasonalityModel | None) -> Mapping[str, str]: ...
def registry_hash_for(specs: tuple[StrategySpec, ...]) -> str: ...
~~~
返回均为小写64hex SHA-256。模型按生产者公开字段形成规范投影，经M1 `canonical_json_bytes`编码：UTF-8无BOM、键排序、紧凑JSON、尾LF、Decimal字符串、拒绝非有限数/重复键。包含最终选定模型、预处理、校准参数、完整证据统计、截止、政策和全部实际source_hashes；不得使用私有hash函数、算法名称、对象地址或pre-calibration内容代替公开结果。
去自引规则固定：各类型只去自身`model_set_id/reference_id/model_id`；ForecastModelSet额外仅在其内嵌evidence的hash投影中去`model_id`和`evidence_id`。evidence_id也可能派生自最终model_id，故只去模型回指仍会循环。其他证据身份（policy/product/session/event/barrier/geometry/horizon/label_version）、样本/误差/截止/status全部保留，不按“字段名像ID”泛化删除。
生成顺序为最终参数/校准及无回指证据内容→集合content_hash/集合ID→填所有evidence.model_id→按完整证据去自身evidence_id生成证据ID→封装最终模型。集合ID由最终内容hash按既有身份格式生成，不能沿用校准前集合ID；证据ID生成同样使用规范SHA-256及既有格式。最终发布记录完整保留两类ID并核验一致性；投影不能泄漏到公开模型或证据文件。source_hashes/models/fit_config不得藏本集合/本证据派生ID或本最终artifact hash以重建循环。
无序集合排序固定：evidence按去自引投影的规范字节排序且同身份不可重复；SeasonalBucket按(product,session_kind,slot_index,duration_seconds)，observations按observation_id，registry按strategy_id且重复ID拒绝。feature_keys、树节点、系数、CDF等有语义顺序的数组保持原序；volatility_samples保留03的升序规则。完整artifact/manifest文件hash不去任何字段，绑定所有最终ID及反向引用。
model_hashes_for 位于 ak_trading.v2.decision.pipeline，replay 与 M5 复用同一公开函数。令 B 表示 "seasonality" in forecast_models.source_hashes，K 表示 forecast_models.feature_keys 中是否有 SEASONAL: 键。K 为真而 B 为假必拒绝；不能因某次请求的季节性值缺失而放过。B 为真时必须提供合法 seasonality_model，来源值须为小写 64hex 且严格等于其 content_hash()；B 为假时必须传 None。B 为真、K 为假可以合法存在：实际输入快照包含该变换，最终预测器没有选择其数值列，来源仍须保留。禁止用 dict.get 将“缺键”与非法 null/空串合并处理。

返回防御性不可变映射，键恰为 forecast/payoff/regime_reference，且当 B 为真时恰多 seasonality 一键；每个值只取相应生产者的 content_hash()。原 reference 身份及最终模型/证据身份核验照常执行。随后构造的快照若含 SEASONAL 行，必须存在上述相符绑定；使用适用的已登记季节性列时由 M2 用该同内容句柄生产，不能静默换成原始列。日线按 005 不调用季节性变换；一个同时服务分钟和日线的集合不会因单次日线请求没有 SEASONAL 行而删掉集合的已绑定来源。真正不使用季节性的集合给 M2 显式传 seasonal=None。错误依赖不进入新风险事务，已有仓沿最后已验证依赖继续风险退出。

> （20260917-r1 仲裁明确适用于本次）model_hashes 仍恰为 forecast/payoff/regime_reference，且仅按既定季节性绑定规则增加 seasonality。exit registry、binding、condition version、continuation model 不得塞入此映射。strategy registry、factor registry、exit registry 保持独立哈希轴。004 列明的去自引投影不因本次增加任意可删 ID；模型或证据身份改变按实际来源重建。

`registry_hash_for`为完整排序StrategySpec规范对象数组的hash，含代码/参数/validation_stage等全部字段；其规范数组bytes即资格验证所称registry原件。
M4上下文/检查点与M5报告/资格统一调用这两个公开函数；`model_bundle_sha256=SHA256(canonical_json_bytes(dict(model_hashes)))`。不复制另一套编码器，不将完整模型文件hash与去自引content_hash混同。
**反例及重跑：** 改最终温度/一条证据误差/截止/一个bucket改变对应内容hash；只改显示ID不改变投影hash但身份校验必须拒绝，完整artifact hash变化；证据/registry输入重排结果一致，feature_keys重排改变hash，None季节性无第四键。覆盖evidence循环、来源错配及M4/M5逐字一致，重跑R1、R2、R3、R4、R5。

执行时再核验实际execution_nano及当前资格/模型/规则，过期或发布后失效的pending OPEN/ADD取消未成交部分，不能按旧decision时间补成交；真实已发生的Fill按003入账而非因资格过期抹除，剩余仓位仍退出。REDUCE/EXIT不套新增风险预测TTL。

## 5. 一折一研究run与空仓分段激活
