## 1. Q01：同 kind 跨连续片段累计槽号

**所有者：M2 实现映射/拟合/变换；M1 提供完整历史日历与锁定契约；M4/M5 传递冻结日历。** 保持 SeasonalBucket 七字段及 SeasonalityModel 六字段，不新增 segment 字段。

桶键仍为 `(product, session_kind, slot_index, duration_seconds, calendar_version)`；calendar_version 来自模型及经核验的 SessionWindow。日内适用频率为 60/300/900/1800/3600 秒，不新增日线季节性定义。

对同 product、同 trading_day、同 kind 的全部已声明连续 SessionWindow，按 start_nano 升序得到 `W0...Wk`。设 `D=duration_seconds*10**9`、`N_j=floor((W_j.end_nano-W_j.start_nano)/D)`。

W_j 内完整 bar 必须满足 `bar.start_nano=W_j.start_nano+i*D`、`bar.end_nano=bar.start_nano+D<=W_j.end_nano`，其中 `0<=i<N_j`；唯一 `slot_index=sum(N_h for h<j)+i`。DAY/NIGHT 分开累计，每个交易日重新开始。

累计量取日历计划完整槽数，绝不取实际观测行数。前段缺一根、缺整段或无成交，后段槽号均不前移；每段开盘槽身份保留。聚合以各段起点为锚，午休/小节休息不拼 bar，不足一个请求周期的尾段不进桶。

每个桶每 trading_day 最多一条观测。先按 §2 的 PIT 截止过滤，再核对槽身份：同一 bar 完整规范内容相同才幂等去重；同时可见的冲突记录拒绝，禁止 setdefault/输入顺序决定赢家。多合约争用同产品日槽时也拒绝，宿主须按事前冻结的选约记录提供唯一训练合约；不平均、不事后择优、不跨合约算收益。

calendar_version 绑定不可变日历原件。为识别同版本异模板，按上述片段顺序比较模板 `[(start_nano % 86400000000000, end_nano-start_nano), ...]`，按 product/kind 分组；移除具体日期/session_id，仅保留 UTC 日内起点与段长，不因周末夜盘归属差异误判。

一次拟合实际使用的日历必须同一 calendar_version，混版本拒绝生成一个模型；同一模型使用的同产品/kind 模板必须一致。同 calendar_version 出现不同模板为 `INVALID/calendar_template_mismatch`，拟合拒绝，不能混桶或暗换版本。真实历史模板改变须由 M1 冻结相应日历版本，M2 按兼容版本分别拟合，缺模型时缺证据。

变换所传 sessions 须包含模型训练区间的原日历、当前交易日全部片段及必要前槽；M4/M5 在装载时核验这些原件与模型训练来源绑定。变换比较训练模板与当前模板；无训练日历原件为 `MISSING/calendar_evidence_missing`，版本不同为 `INVALID/calendar_version_mismatch`。不从 model_id、观测行或私有全局表反推模板。

**手算：** 20 个训练日，AM 两槽量均 10、PM 两槽量均 100，DAY 槽必须为 0/1/2/3，四桶各 20 日；下一日 PM 首槽量 100 得 `100/100-1=0`，不能得 9。删 AM 的观测不改变 PM 的槽号 2；只有缺失样本数变化。60 秒下 AM150/PM90/NIGHT100 应有 DAY240+NIGHT100 共 340 个计划桶。

## 2. Q02：收益唯一采用前收至当前收盘

**所有者：M2 的 seasonality.py/factors.py；M4 上下文调用，M5 训练与影子宿主适配；M1 锁定下列公开签名。**

~~~python
# ak_trading.v2.seasonality；新增关键字必填，不设默认 None
def seasonal_values(model: SeasonalityModel, bar: MarketBar,
                    sessions: tuple[SessionWindow, ...], decision_nano: int, *,
                    previous_bar: MarketBar | None) -> tuple[FactorValue, ...]: ...

# 原拟合签名保持不变
def fit_seasonality(bars: tuple[MarketBar, ...], sessions: tuple[SessionWindow, ...],
                    fit_start_nano: int, fit_end_nano: int) -> SeasonalityModel: ...

# 保持 004：只去自身 model_id，其他最终字段全部参与规范内容哈希
def content_hash(self) -> str: ...  # SeasonalityModel 的方法
~~~

绝对收益固定 `a_t=abs(ln(bar.close/previous_bar.close))`；两价为正有限值。量列为 `V_t/median_volume-1`，收益列为 `a_t/median_abs_return`，后者不减 1；不得以 `abs(ln(C/O))`、0 或模型内暗存前收替代。每段首槽在其独有桶中统计含跳空的这一收益，不另造第三列；先算完整 close-to-close 再取绝对值，不能将开盘跳空与槽内变动分别取绝对值后相加。

previous_bar 必须是同 contract_id/product/duration 的日历应有前一个完整槽，且两根 complete、结束及各自 available_at 均不晚于 decision；先用 §3 网格验证邻接。可跨明确合法休市含跳空，不能越过缺失计划槽、坏行或换合约；前槽尚不可见视为缺失，不回退到更早收盘。

调用者必须显式给 previous_bar，包括 None。None 或应有前槽不可见时收益行 `value=None,status=MISSING,reason=previous_bar_missing`，量列仍独立计算；传错合约/频率/槽的非空前收为收益行 INVALID。缺价为 MISSING，非正/非有限价为 INVALID；不污染输入合格的量列。共同日历/模型无效则两列均不可用。

fit 的当前样本区间固定 `fit_start_nano<=bar.start_nano<bar.end_nano<=fit_end_nano`，并要求 `available_at_nano<=fit_end_nano` 且非空；以 fit_end 为 PIT 截止过滤后再去重。按合约/频率及应有前槽找 previous，不按存储行邻接。可显式传入训练起点前恰需的前槽作收益上下文，但它不作为训练日样本，仍参与来源与时间核验。

拟合可以使用截止前已实际可见的历史版本，但不能重写原 bar 的 available_at/imported_at，不能把晚到修订回填进早期已发布特征。未来才可见的修订不触发此前拟合或决策的冲突；同一截止同时可见的冲突仍拒绝。

sample_days 固定为该桶去重后、身份/完成/PIT 合格的交易日数；量和收益分别统计有效日数，各自不足 20 日则对应 median 为 None。每列中位数只取该列合法值，偶数项取中间两值均值；0 量/0 收益是合法样本。逐桶两列有效日数与排除原因留在 M2 拟合证据，可由冻结输入重算，不增加模型字段或隐藏传参。

变换时缺桶或对应 median=None 为 MISSING/缺证据；median=0 为 INVALID/零分母，无数值，不补 1。previous_bar=None 不影响已有合格量桶；缺量也不减少可用收益样本。两列始终保留，状态/原因分别记录。

模型必须满足 `fit_start_nano<fit_end_nano<=decision_nano`，未来模型两列 INVALID/model_fit_after_decision。可用量行 available_at 取 `max(bar.available_at_nano,model.fit_end_nano)`，收益行再包含 previous_bar.available_at；不得用 decision 掩盖未来输入。None 时保留未知，不用 end/imported_at/当前时钟补源首见。

模型在一折内冻结。M5 仅用训练段及必要前槽调用 fit，保留日历原件、选约与样本证据；M4/M5 把同一 bundle.sessions 传给 build_feature_snapshot。M2 在该入口按当前 decision 选择并验证 previous，再调用 seasonal_values；直接调用者承担相同前槽责任。M3A 只消费 FactorValue，不能重算或静默替换原始收益因子。

**手算：** 20 个同槽合法训练对均前收 100、当前收 110，median_abs_return=ln(1.1)。评估前收 100、当前 O=C=121，收益比 `ln(1.21)/ln(1.1)=2`，不能为 0。当前量与历史中位量均 100 时量列为 0；显式 previous_bar=None 时仅收益列 MISSING。前收晚 1ns 才可见及 fit_end=decision+1ns 各有不可用断言。

## 3. E02：显式日历进入底层公开计算器

**裁决选择必填 sessions 方案；不把“高层已补齐”当底层前提。** M1 负责日历原件、覆盖证明及原 visible_bars/aggregate_bars 语义；M2 负责每个入口实际检查计划槽；M4/M5 负责提供完整冻结输入及调用链。

~~~python
# ak_trading.v2.factors
def compute_factor(spec: FactorSpec, bars: tuple[MarketBar, ...],
                   decision_nano: int, *,
                   sessions: tuple[SessionWindow, ...]) -> FactorValue: ...

# ak_trading.v2.baseline
def baseline_values_v2(bars: tuple[MarketBar, ...], decision_nano: int, *,
                       sessions: tuple[SessionWindow, ...]) -> tuple[FactorValue, ...]: ...

                          sessions: tuple[SessionWindow, ...]) -> tuple[FeatureSnapshot, ...]: ...
~~~

上述新增关键字全部无默认值，省略即调用错误；不新增公共 dict、隐式缓存状态参数或默认 weekday 日历。build_feature_snapshot 的八个原位置参数及返回类型保持 02 原签名，其已有 sessions 必须继续传入 compute_factor、baseline_values_v2、seasonal_values；fit 自行执行同一网格核验。

sessions 是覆盖所需历史窗口、前槽和当前完整交易日的完整计划，不能由 bars 中出现过的 session_id 反推。SessionWindow 仅列开市段，本身无法证明一段无记录日期是休市；M1 在冻结包原件/覆盖证据中确认所请求范围开闭市均已核验，M4/M5 装载时检查。没有该证明，调用方必须显式传空 sessions，不能把残缺表当完整计划。

空 sessions、所需日期无覆盖证据或相关 evidence_status=UNKNOWN 时为 MISSING/calendar_unknown，不能按无缺槽 READY；fit 无可核验日历则拒绝生成可用模型。SCENARIO 完整计划只支持明确合成研究，证据等级原样保留，不能升级 VERIFIED/真实影子。结构冲突、重叠片段或身份不符为 INVALID。

分钟网格按每段起点和请求频率展开完整计划槽；日线网格取完整日历中 distinct trading_day，每个交易日一槽，完成时点为该日最后会话结束，86400 不作自然日步长。显式休市无槽；声明开市而缺整段/整日仍是缺槽，不能以 session_id 改变或日线类型直接判连续。

先按 decision 过滤未来结束/未完成/尚不可见的源内容，再对可见候选去重核验，最后与应有网格比对。未来行不参与历史冲突或 hash；已结束却缺合格观测的槽在内部保留缺失标记，不伪造 MarketBar 的价格/首见时间，也不把旧观察移到该槽。

当前目标为该频率满足 `end_nano<=decision_nano` 的最后计划完整槽；缺当前观测不能回退至更早一根而报 READY。滚动窗口在缺槽/相关必需字段坏行/换合约处断开，重新积累原规定完整窗口；Wilder 重置并重新收集 n 个连续 TR。量仓缺失仅中断依赖该字段的算子。

有缺口后的当前有效 bar 但连续输入不足时为 WARMUP，并保留 expected_slot_missing 等断点原因；当前必需值缺失为 MISSING；日历无法证明时优先保留 calendar_unknown，不伪装成普通预热。新十项与全部已登记同周期十四项基线均保留 FactorValue 行，META/SEASONAL 为额外列。无法确定合约/频率/有效快照锚时拒绝 READY，宿主按请求登记不可用，不能默认 d60 或删除失败时点。

legacy_daily_baseline 的 decision_nano 是本次查询截止。对当前日线锚 b，仅在 b 完整、首见已知且 `d=max(b.end_nano,b.available_at_nano)<=decision_nano` 时生成该锚的历史对照快照，snapshot.decision_nano=d；仅消费 end<=b.end 且 available_at<=d 的原始前缀。逐快照在该 d 先 PIT 过滤再去重、验证计划日槽，不能先按整个查询截止去重而让晚到修订破坏较早快照。

旧十四项仍只读调用 v1 factor_registry/build_factor_rows，但先切出该锚合法连续前缀；不得 dropna 后跨缺日喂旧实现。已有源时间原样传递，各输出 available_at 取实际消费输入最大值，含当前锚。未知首见的行是缺失断点，不能补成 end；无可见锚返回空 tuple，M2 对照生成器按原请求记录十四项 UNAVAILABLE 及原因，M5 保留原计划分母，不能计作 MATCH。全部结果保留 legacy-v1 标签，v1 文件不修改。

**手算：** 日历 AM 三槽、PM 两槽，只有 AM 前两根收 100/110、PM 首根 121；n=2 的 MOM001/VOL004 均不得 READY，PM 首根不越过 AM 尾缺槽。补齐合法 AM 尾槽后才能按完整窗口计午休跳空。另删 PM 首槽、删整个中间会话分别断窗。

## 4. Q03 与 E07：源定义、算子和实际输入各自绑定

**所有者：M2 的 factor_specs.py/factors.py/baseline.py/seasonality.py 及产物生成；M1 提供原规范编码与签名锁，独立审核者核验提取原件。**

本十项库因子的 FactorSpec.source_sha256 唯一原像为对应 `FactorLibrary.factor(factor_id)["factor"]` 的完整原始 23 字段对象，经 M1 canonical_json_bytes 编码后的 bytes；不含外层 catalog_id、适用品种映射或检索结果，不是四字段转录子集，也不是 CSV/SQLite/ZIP 文件哈希。BASE 继续使用其原只读对照定义来源，不伪造库内 23 字段记录。

23 键固定为 `factor_id,name,layer,family,role,scope,formula,inputs,frequency,parameters,direction_hypothesis,transform,data_requirement,available_at_rule,minimum_history,source_ids,source_urls,evidence,caveats,priority,implementation,backtest,version`，缺/多字段拒绝。原值及类型逐字段保留，公式/标点/空格不 trim 或改写，版本 "1.0" 不变数字，空串不变 null；源 parameters 文本不与 FactorSpec.parameters 对象混用。

编码遵 M1：UTF-8 无 BOM、非 ASCII 原文、键排序、紧凑 JSON、恰一个尾 LF、拒绝重复键/非有限数。`source_sha256=SHA256(canonical_json_bytes(source_factor_object))`，返回小写 64hex；同一源因子的六频率共享此源哈希，频率/别名/年化差异由实际 FactorSpec 另行绑定。

M2 后续交付只含本十项的原始对象与提取记录，记录 catalog_id=`china_futures_v1_20260913`、原 factor_id/version、只读查询/提取方式、原 ZIP/CSV/SQLite 各自文件 SHA-256、记录与源行的对应关系。独立审核者从原 CSV/只读 SQLite 核对这十项全部字段及 hash，不用同一个转录 helper 自证；运行期不要求查库，不重扫或修改整包。已有来源报告可复用，但须核验真实原件绑定。

令 `H(x)=SHA256(canonical_json_bytes(x))`。每个实际 spec 分别计算 `spec_hash=H(encode_record(spec))`、`parameter_hash=H(dict(spec.parameters))`；后者在既有 manifest.provenance.parameter_hashes 以 factor_key 登记，前者覆盖全部十一字段，包括参数版本、频率/lookback、required_fields、formula、source_sha256。

每个公式实现另登记 `operator_hash=H({"operator_version":spec.operator_version,"formula":spec.formula,"code_hashes":实现所用模块相对路径到实际文件SHA-256的映射})`，以 factor_key 写入既有 provenance.code_hashes，模块原文件 hash 同时留存；不能用源定义哈希或算子名称代替实际代码证据。不向 FactorSpec/manifest 根新增字段，不执行公式字符串。

FactorValue.quality.input_hash 绑定实际 spec 完整内容、实际消费 MarketBar 的完整 encode_record 内容（含数值/质量/源时间）和所需日历片段；季节性还绑定当前/实际前槽或显式缺失事实、对应模型 content_hash。无序来源按身份/时间稳定排序，有语义顺序的数组保持原序，再规范编码；bar_id 仅是身份，不能替代内容哈希。缺槽位置与决定连续性的计划片段也属于消费证据。

snapshot.quality.input_hash 及稳定身份绑定全部请求同周期 spec、全部输出值及实际参考价/ATR、背景、规则、日历、模型依赖的规范内容；source_bar_ids 保留实际来源 ID 列表但不承担内容校验。Wilder 绑定自最近重置后的全部实际递推输入，不能只绑定最后 n 根。不把未来 bar/不可见修订或整包 manifest 哈希塞入历史身份；整包哈希只留运行溯源。

**反例：** 同 bar_id 将 VOI009 的 V10/OI100 改为 V20/OI100，值 0.1→0.2，input_hash/snapshot_id 必须改变；即使结果数值不变，只改实际 spec 的 source_sha256/operator_version/parameters 也必须改变身份。只改源对象 caveats，source_sha256 也须变；单纯重排 JSON 键不变；删除规范尾 LF 的 bytes 是不同原像。追加未来 100 根或尚不可见修订，历史值/字节/hash 不变。
