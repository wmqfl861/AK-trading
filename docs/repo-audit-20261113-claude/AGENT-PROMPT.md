# 给本地 agent 的提示词（第五轮，第二批）

用法：把下面代码块里的全文发给本地 agent（Root）。

你说过需要你决定的事项都按我的推荐做，所以这一份没有留待填的空。它替你定下的事都写在 [DECISIONS.md](DECISIONS.md) 里，最要紧的五件是：

- 先出 v1 日线的报告（把已有的七年结果读出来），按原规格跑 v2 日线报告的 H7 取消。
- 研究资金统一按 100 万元。
- 规则文件里加一条“需要用户决定的事项默认按外部审核的决定执行”，同时写明哪些事不适用。
- 分工表固定为本地 agent 记录在案的你最新一次指令。
- 策略报告的汇总表和结论照常入库。仓库现在是公开的，入库就等于公开；之前的结果文档也是这样入库的。

你不同意哪一条，发之前改掉提示词里对应的那一行就行。

```text
本批任务：按第五轮外部审核的文档完成第二批。完成或被阻塞后停止，不自动开始下一批。

一、先取得文档并核实

1. git fetch origin，把分支 claude/repo-audit-20261113 合入 main。它只新增 docs/repo-audit-20261113-claude/ 目录。记录合入后的 HEAD。
2. 按顺序阅读该目录下的 DECISIONS.md、NEXT-BATCH.md、REVIEW.md。
3. REVIEW.md 是外部审核意见，不是产品硬审核。DECISIONS.md 是我认可的决定，见第二节。涉及代码语义的地方仍由计划作者裁定；裁定和外部文档不一致时以裁定为准，把差异写进状态页。
4. 动手之前，在本机跑 REVIEW.md 附录里标了“请复现”的四条命令，把每条的原始退出码和结果写进 docs/CURRENT-STATUS.md。结果和文档不一致的地方，以你的实测为准，并写明差异。

二、我的决定

- 从现在起，需要我决定的事项，默认按最新一轮外部审核目录里的 DECISIONS.md 执行，不用等我逐条确认。这一条按 DECISIONS.md 第五节的原文写进规则文件（G7）。
- DECISIONS.md 没有覆盖、又确实需要我决定的新事项：记进状态页“待决”一栏，继续做不受影响的工作，不要因此停下整批。
- 下列事项不适用默认值，必须有我本人的明确指示：开启真实交易或发出任何真实报单、撤单；读取、打印、修改凭据；消耗最终 holdout；仓库可见性、令牌、防火墙、服务、数据库角色、系统设置、交易客户端界面的实际操作；删除输入数据、合同锁、验收清单、审核结论或失败记录；向仓库以外发布代码或研究结论。
- 本批采纳 DECISIONS.md 的 J1–J18。其中：
  · H7 取消，由 K40 取代。H6 并入以后的 v2 日线路线。H5 现有两条冷链按 FAIL 保留，不再启动新的。H8 由 K12 取代，profile09 不恢复，profile10 不启动。
  · 研究资金统一按 100 万元。
  · G1–G4 改为常设，完成标准加上“全量失败清单相对合入前没有新增”，回归基线每批前移一次。
  · 分工只写在 PROJECT-MODEL-ROLES.md 顶部的现行分工表里。表里填你记录在案的我最新一条直接分工指令，固定到 K40 的第一份报告入库为止。
  · 策略报告的汇总表和结论照常入库（仓库目前是公开的）。输入数据包、逐笔明细、候选分支、验收清单、合同锁不上远端，直到我告诉你仓库已转私有。
  · 授权对 r1、r2 两份真实输入候选的非留出区间做只读统计（K42、K02b）。不修填任何字段。
  · 授权清理磁盘上的中间产物，范围和必须保留的东西见 DECISIONS.md 的 J16。清理前把类别和大小写进状态页；拿不准的不删。

三、本批任务

范围、做法、交付物和验收都在 NEXT-BATCH.md 第二到第五节，按那里的顺序和分线执行：

关键线（一条开发，一条独立审核）
1. K40-A：把已经通过独立审核的 v1 七年结果写成一页报告。只读已有输出，不新跑回测。
2. K40-B：补资金、成本敏感性和两个对照。先由计划作者写短计划。

支撑线
3. S1：规则文件按 DECISIONS.md 第五节的原文修改；加 .gitattributes；改 requires-python；文档里的公网地址换成占位符。先做这一项。
4. S2：r6 的全量基线入库；CI 加两个工具的测试。
5. K02b：在真实螺纹钢日线上实测跨周期背景的可达性。只测量，不改代码。
6. K42：真实输入就绪清单。
7. K10b：上下文构造复用交易节元组；标签模块的缓存改为持有对象。这是本批唯一确定要改产品代码的一项，写集请计划作者确认，走独立硬审。
8. K12：K10b 合入后，5、20、60 个交易日三档 profile。
9. K25：基线失败分诊表。只列表，不改测试。
10. J7：请计划作者写合同锁分级的变更申请。只写，不实施。

K40-A 和 S1 可以同时开始。

四、要求

- 涉及语义的地方先有计划作者的裁定，不自行决定。
- 每个产品改动：改动前后各有一次全量，按用例比较，新增失败必须为 0；预期内的变化逐条列出原因。
- 不为了让测试通过而修改预期、刷新冻结哈希、添加 skip 或 xfail、放宽门槛。
- 完成标准：独立硬审无条件 PASS、合入 main、CI 通过、全量无新增失败。
- K40-A、K40-B 的报告要有独立复算：审核者从同一批源文件独立重算，表格逐格相同。
- K02b、K42、K12、K25 交付的是表格，不需要独立硬审，但每张表都附上产生它的命令和原始退出码。
- K40 的报告是写给我看的：一页，先结论后表格，结论只写事实，不写交易建议；哈希和运行标识放进 CHECK.json，不放进正文。
- 每项完成即提交并推送 main。提交说明写清改动、命令、原始退出码、passed/failed 数和全量对照结果。不为每一步新建过程文档。

五、本批不做

- 不启动 H5′、H6、H7，不启动新的冷链，不恢复 profile09，不启动 profile10。
- 不重新冻结 T7 夹具，不实施合同锁分级，不改“明确方向”的定义和任何准入条件。
- 不改统计门槛、风控参数、窗口长度、留出集边界，不放宽 synthetic=false 的日历门槛。
- 不做 K11、K13、K04b、K41，不续接 N8、DISPATCH，不做完整 shadow、Forward 采集、本地 paper。
- 规则文件只做 DECISIONS.md 第五节写明的替换和插入，其余内容不动。
- 不修改 docs/repo-audit-*-claude/ 下任何外部审核文件。
- 不做全库换行规范化或格式化。

六、边界

- 不读取、不打印、不修改 .env 和任何凭据。
- 仓库可见性、令牌、防火墙、服务重启、数据库角色、Windows 系统设置、交易客户端界面只由我本人操作，你只准备步骤。
- 保持 enable_trading=False、observer=hold、broker=NOT_RUN、真实 send/cancel 为 0/0。
- 遇到 NEXT-BATCH.md 第七节列出的任一停止条件，停下对应任务并写进状态页，其余任务继续。

七、状态与收尾

- 状态只更新 docs/CURRENT-STATUS.md。页首三行给我看，每行不超过 40 个字：本周能看到什么；卡在哪；需要我做什么。第三行列出 DECISIONS.md 第四节里我还没做的事，不要写“暂无”。
- K40-A 的报告入库时，把三句话结论抄到状态页页首。
- 本批全部完成或被阻塞时停止，给我一页摘要，包含：
  1. K40 的三句话结论和分年表，直接贴出来；
  2. 第一节复现命令的实测结果；
  3. 各任务的状态、合入的提交号、阻塞原因；
  4. K02b、K42、K12、K25 四张表各自最要紧的一个数字，加文件位置；
  5. 计划作者各项裁定的摘要，以及与外部文档的差异；
  6. 全量基线的通过、失败、错误数，以及本批前后的对照；
  7. 状态页“待决”一栏的全部内容。
```

## 发出去之后

本地 agent 做完会停下来给你一页摘要。把它连同仓库地址发给我，我做第六轮：核对 K40 的报告，看 K02b、K42、K12、K25 四张表，然后定第三批（见 [NEXT-BATCH.md](NEXT-BATCH.md) 第八节）。

只有你本人能做的事在 [DECISIONS.md](DECISIONS.md) 第四节，最要紧的是前两件：仓库转私有，轮换行情服务令牌。
