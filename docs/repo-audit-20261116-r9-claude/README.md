## 一段话结论

第五批的说法全部属实：K45-R001 按事先写定的规则做完，检验段只评分一次，独立复算没有差异；我用已入库的文件核对了 1,104 项，没有不一致；全量测试原有的 6,135 项逐项没有变化，新增的 73 项全部通过。按预定规则，分钟模式在 5 分钟和 15 分钟上达到了“继续研究条件”。但这个结果现在只能读成“模型看得出价格接下来会不会动”，还不能读成“看得出往哪边动”：三类（涨、跌、持平）合在一起的分数，只靠“会不会动”就能达到，我用合成数据验证了这一点。所以第六批只做一件事：把 R001 已经评过分的那批预测拆开看一次，回答“有没有方向信息”和“这点信息够不够付买卖价差”，再按事先写好的表决定要不要在更长的数据上再检验。暂停的工程项这一批不恢复。

只用标准库和仓库里已入库的文件；第二个另外调用仓库的统计模块，数据是合成的。在仓库根目录运行。

| 探针 | 回答什么问题 | 我这边的结果 |
| --- | --- | --- |
| `k45_r001_published_tables_recheck.py` | R001 的正文、九份表和清单相互对不对得上；登记的哈希是否等于入库文件；结论按设计重算是否相同。另外按分箱粗算改进落在三类里的哪一类 | 退出码 0；1,104 项，不一致 0 项；不到 1 秒 |

```text
python -B -X utf8 docs/repo-audit-20261116-r9-claude/probes/k45_r001_published_tables_recheck.py
```

第二个探针还有一个 `--frozen-dir` 模式，读 R001 封存的概率和标签，先核对哈希、复现已入库的主表，再输出分解。外部审核方没有这两份文件。这个模式是给项目内的独立审核者在 K47 里做第二实现复算用的，开工复现时不要运行。
