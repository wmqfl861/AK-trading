## v4 与 v3 的区别

v3 的路线是“修热点 → T7 DAILY → RB DAILY 报告 → MINUTE”。执行到一半时，这一轮发现路线的前提不成立：v2 的策略在真实时钟和日历下开不出仓。v4 做四处调整：

1. **正确性排在速度和验收之前。** 先修入场确认和震荡状态的跨周期结论，并且用真实形状的夹具把它们守住。
2. **每个昂贵运行之前先做可达性预检。** 资金、样本、日历、确认四项里任何一项注定零成交，就不启动。
3. **日线路线由你选。** 我的建议是先用 v1 出一份有信息量的基线报告，v2 日线另行登记专用设计。
4. **提速改成“加一层索引”，不再逐个函数立项。** 日历索引和上下文共享各作为一个整体交付。

v3 里仍然有效的部分不变：并行上限、工程运行可重跑、一页状态页、CI、以合入 main 为准。

### 阶段二：第一份有信息量的报告

**K40 v1 日线基线报告**（J2 选 A 时）：

- 策略：`donchian_trend`、`ma_trend`、`zscore_reversion`，参数用代码里的默认值，不调参。
- 数据：数据库里螺纹钢全部有日线的合约，时间尽量长。先做 RB，流程跑通后同样的配置做 M、I。
- 必报内容：
  - 每个合约、每个自然年的净盈亏，以及“全部年份里有几年为正”。参数是事先固定的，所以分年结果就是样本外的稳定性检验。
  - 资金敏感性：100 万、30 万、10 万、5 万元；每档报告开仓被拒次数。
  - 成本敏感性：手续费翻倍、滑点翻倍、保证金乘 1.5。
  - 与“永远空仓”和“买入持有近月”的对照。
- 明确写出的限制：手续费和保证金是假设值；不换月；日历未核实。结论标 `SCENARIO`。
- 现成的工具：`scripts/backtest_history.py`、`tools/experiments/historical_daily_scenario_compare.py`、`historical_daily_capital_stress.py`、`historical_daily_chronological_transfer.py`。主要工作是扩大输入范围、把四个工具的输出汇成一份报告。

**H6′ T7 DAILY 验收**：验收内容不变，夹具的日历改成带夜盘和多个交易节，K 线可用时刻晚于收盘。在这样的夹具上通过，才说明日线链路在真实数据上有可能工作。
