# AK-trading 项目功能说明（重点：策略部分）

日期：2026-11-10 · 依据：`main@b75d220` 的源码 · 作者：Claude（第四轮外部审核）

> 这份说明只描述仓库里的代码现在能做什么、做到了哪一步，不评价好坏。问题和建议见 [REVIEW.md](REVIEW.md) 与 [OPTIMIZATION.md](OPTIMIZATION.md)。
> 每个结论都能在源码里找到出处，文中用“文件:行号”标出关键位置。

## 一、一句话概括

这是一个国内期货的**数据仓库加策略研究平台**：把行情和交易所规则存进本机数据库，在冻结的数据文件上离线研究策略，并留有连接交易客户端的接口。真实下单的通道已经写好，但全程关闭。

到今天为止，它**没有产出过一份可以判断“某个策略是否有效”的正式报告**。已有的结果是老一代引擎在螺纹钢日线上的情景比较。

## 三、策略部分

仓库里有三代策略代码，互相独立。

### 3.1 最早的演示策略

`src/ak_trading/strategy.py`：一个双均线多空策略，70 行。只用来验证“行情更新 → 信号 → 目标仓位 → 日志”这条链路，不是正式策略。

### 3.2 第一代策略库（v1）：四个日线策略

位置：`src/ak_trading/futures/strategies.py`。每个策略每天收盘后给出方向（多、空、空仓），第二天开盘按固定手数执行。

| 策略 | 规则 | 默认参数 |
| --- | --- | --- |
| 唐奇安趋势 `donchian_trend` | 收盘价严格突破前 N 日高点做多、跌破前 N 日低点做空；用更短的通道离场 | 入场 40 日，离场 20 日 |
| 均线趋势 `ma_trend` | 快线在慢线之上做多，反之做空；只在趋势状态下持仓 | 快线 20 日，慢线 60 日 |
| Z 值回归 `zscore_reversion` | 价格偏离前 20 日均值超过 2 个标准差时反向开仓；回到 0.5 以内平仓，超过 4 止损，持有不超过 20 日 | 20 / 2.0 / 0.5 / 4.0 / 20 |
| 期限结构 `term_structure_carry` | 用近月和远月的价差算年化展期收益，超过阈值时只交易近月 | 阈值 3% |

配套的 `scenario_backtest.py` 是单合约回测：上一根日线出信号，下一根开盘成交，含手续费、滑点、保证金检查和逐日权益。手续费、保证金是你在配置里填的假设值，不是逐日的交易所真实参数；不自动换月。

**已有结果**（第三轮审核引用的 10 月 14 日 RB 日线情景，14 个合约，初始资金 100 万元）：

| 策略 | 净盈亏合计（元） | 盈 / 平 / 亏的合约数 | 平仓笔数 |
| --- | ---: | --- | ---: |
| 唐奇安趋势 | 42,305 | 10 / 1 / 3 | 19 |
| 均线趋势 | 5,524 | 7 / 1 / 6 | 59 |
| Z 值回归 | −45,372 | 2 / 1 / 11 | 53 |

这是样本内的情景比较，没有做样本外检验。同一个唐奇安策略在 1.5 万元资金、18% 保证金下净亏 9,350 元，开仓被拒 804 次。

### 3.3 第一代概率研究

位置：`src/ak_trading/probability/`。思路是先统计“类似情况下价格接下来怎么走”，再决定用哪个策略。

- 14 个日线因子：收盘价、前 20 日高低点、ATR14、效率比 ER20、波动率、MA20、MA60、均线差、Z 值、距高低点的距离、量比、持仓量变化。
- 标签：未来 1、5、20 日内，价格先碰到上方还是下方的 0.5、1、2 倍 ATR。
- 比较对象：突破、回归、回踩、有限库存网格、按概率抽样、空仓。

9 月 8 日的首轮真实研究里，选择器按预设门槛**全部选择空仓**，没有得出盈利或胜率结论。

### 3.4 第二代策略库（v2）：项目当前的主线

位置：`src/ak_trading/v2/`。它不是“一个策略”，而是一条五段流水线：

```
行情文件 → ① 因子 → ② 概率预测 → ③ 七类策略各出一个候选 → ④ 联合闸门与选择 → ⑤ 虚拟成交与账本
```

每类策略都有分钟版（`_m1_v2`）和日线版（`_d1_v2`），共 14 个。分钟版最长持有 30 个交易分钟，不隔夜；日线版最长持有 5 个交易日。

#### ① 因子（M2）

- 10 个来自因子库的计算器：动量 3 个（MOM001、MOM003、MOM010）、反转 1 个（REV001）、量仓 3 个（VOI001、VOI007、VOI009）、波动 3 个（VOL001、VOL004、VOL005）。
- 基线量：收盘价、MA20、MA60、ATR14、ER20、前 20 根高低点、量比、开盘跳空。
- 分钟线另有日内季节性（同一时段的历史统计）。
- 所有计算只用决策时刻已经完成并且已经可见的 K 线。

#### ② 概率预测（M3A）

对每个决策时刻，预测未来一段时间的几件事：

- **方向**：涨、跌、持平的概率。
- **路径**：先碰上方障碍、先碰下方障碍、都不碰、无法判断的概率。障碍是 0.5、1、2 倍 ATR。
- **状态延续**：当前的上升趋势、下降趋势、有序震荡、突破等状态能否持续。
- **止损触碰、先回归还是先破位**：给震荡类策略用。

预测期限：分钟线是 1、5、15、30、60 个交易分钟，日线是 1、5、20 个交易日。

模型一共九种，全部用 Python 标准库手写：无条件频率、条件频率、L2 多分类逻辑回归、L2 二分类逻辑回归、深度 2 的梯度提升树、经验分位数、线性分位数回归、经验分布、离散时间竞争风险。每个任务在训练集内部挑损失最小的一种，再用单独的校准段调整。

**市场状态识别**（`probability/regimes.py`）决定哪类策略有资格出手：

| 状态 | 判定 |
| --- | --- |
| 上升 / 下降趋势 | ER20 ≥ 0.5，且 MA20 在 MA60 之上 / 之下 |
| 有序震荡 | ER20 ≤ 0.3，价格在前 20 根的高低点之间，区间宽度够覆盖成本且不过宽 |
| 压缩 | ER20 ≤ 0.3，但区间太窄，覆盖不了往返成本或不足 2 倍 ATR |
| 宽幅震荡 | 区间过宽或波动率处在训练期的高位 |
| 未知 | ER20 在 0.3 到 0.5 之间，或缺数据 |

另有四个附加标记：回踩、突破、事件冲击（开盘跳空 ≥ 2 倍 ATR 或宏观风险标签）、流动性不足。

#### ③ 七类策略（M3B）

所有策略先过同一组准入条件（`strategies/registry.py:769` 的 `admission_decision`），再看各自的价格形态。

**共同的准入条件**（缺一不可）：

- 因子和状态数据完好，状态属于该策略允许的范围。
- 日线背景和当前周期方向一致（代码里叫跨周期一致）。
- 对应的“状态延续概率”达到门槛：普通策略 0.70，马丁格尔 0.85。
- 这个概率有校准证据支持：同一品种、同一状态、同一期限、同一个 5% 概率区间内，校准样本不少于 200 个（马丁 500 个）、分布在不少于 30 个交易日（马丁 60 个），校准误差不超过 0.05（马丁 0.03）。
- “无法判断”的路径概率不超过 0.05（马丁 0.02）。
- 连续 3 次观察都满足条件才出手。
- 平仓后冷却 30 个交易分钟（日线为 1 个交易日）。

**各类策略的价格形态**：

| 策略 | 允许的状态 | 入场 | 止损 / 止盈 | 分批 |
| --- | --- | --- | --- | --- |
| 趋势跟随 TREND | 上升、下降趋势 | MA20 与 MA60 的差不小于 0.25 倍 ATR，且最近 3 根收盘价都站在各自当时的 MA20 同侧 | 1 倍 ATR / 2 倍 ATR，按决策时的参考价冻结，不随实际成交价移动 | 不加仓 |
| 确认突破 BREAKOUT | 趋势、压缩，且带突破标记 | 连续 3 根收盘价越过前 20 根的高点（或低点）外加 1 个最小变动价位；目标价差要覆盖 2 倍往返成本 | 1 倍 ATR / 2 倍 ATR；收盘价回到边界内算假突破，离场 | 不加仓 |
| 趋势回踩 PULLBACK | 趋势，且带回踩标记 | 收盘价先进入 MA20 上下 0.5 倍 ATR 的回踩区，之后某根收盘价重新站回 MA20 并高于前一根（做空相反）；形态 5 根内有效 | 1 倍 ATR / 2 倍 ATR；背景趋势消失即离场 | 不加仓 |
| 区间回归 REVERSION | 有序震荡 | 收盘价先跌到区间下沿之上 20% 宽度以内，之后重新向上穿过这条线且仍在中轴之下；目标价差要覆盖 2 倍往返成本 | 区间外 1 倍 ATR / 区间中轴；收盘价出区间即离场 | 不加仓 |
| 固定网格 GRID | 有序震荡 | 首层同上，位置在下沿之上 25% 宽度处 | 同上 | 三层等量，分别在 25%、15%、5% 宽度处；只有收盘价逆向穿过下一层才加，浮亏本身不触发 |
| 有限马丁 MARTINGALE | 有序震荡，且无突破标记 | 同网格首层；另要求止损触碰概率不超过 0.10、“先回归”证据有效 | 同上 | 三层 1 : 2 : 4，共 7 个单位；整轮预算在首层之前一次冻结，之后不扩大 |
| 等待 WAIT | 任何 | 永远不开仓，只说明为什么不动 | — | — |

**每一轮的资金预算**（`strategies/state.py:160` 的 `freeze_round_budget`）在开仓前一次算好并冻结：

- 计划亏损（按最差成交价到止损价，含双边手续费）不超过权益的 0.5%。
- 压力亏损（跳空 3 倍 ATR、连续 3 个交易日锁仓后再多亏 1 倍 ATR、手续费和滑点翻倍，三者取最大）不超过权益的 2%。
- 压力保证金（保证金率乘 1.5）不超过权益的 10%。
- 单轮最多 7 手。

任何一条不满足，这一轮就不开。

#### 退出规则库（M3C）

位置：`src/ak_trading/v2/exits/`。八类规则，开仓前就和入场策略绑定，持仓期间不换。

| 规则 | 做什么 | 是否已接入策略 |
| --- | --- | --- |
| 原始规则 LEGACY | 上表里的止损、止盈、到期、状态延续概率跌破 0.65（马丁 0.80） | 是，全部策略 |
| ATR 跟踪止损 TRAILING | 盈利达到门槛后启动，止损线只向有利方向收紧 | 是，仅趋势、突破、回踩 |
| 时间衰减 TIME_DECAY | 持仓过了 75% 的时间而盈利不足 0.5 倍初始风险，全部平仓 | 是，仅趋势、突破、回踩 |
| 波动止损 VOLATILITY_STOP | 按当前 ATR 计算的保护线，只紧不松 | 已实现，未绑定 |
| 回撤退出 DRAWDOWN | 整轮净值从峰值回吐超过门槛即离场 | 已实现，未绑定 |
| 阶梯止盈 PROFIT_LADDER | 盈利到几个台阶时分批减仓 | 已实现，未绑定 |
| 信号反转 SIGNAL_REVERSAL | 价格连续 2 根落到 MA20 的不利一侧，可选放量确认 | 已实现，未绑定 |
| 分批数量换算 | 把“减到百分之几”换算成具体手数 | 配合阶梯止盈使用 |

多条规则同时触发时，全平优先，其次取减仓最多的那个。

#### ④ 联合闸门与选择（M4）

位置：`src/ak_trading/v2/decision/`。七类策略各出一个候选，再过第二道闸门：

- 重新核对一遍上面的概率证据、数据新鲜度（分钟线超过 120 秒算过期）、手续费和保证金规则是否已知。
- **条件收益模型**：用这个策略在训练期内的历史回合，估计这一次的保守期望收益和 95% 尾部亏损。要求历史回合不少于 200 个、分布在不少于 30 个交易日，保守期望为正，尾部亏损不超过本轮计划亏损。
- 账户层面：当日亏损不超过 2%，回撤不超过 10%（超过即停止开新仓），总保证金不超过 40%，单策略 10%、单品种 15%、单风险组 25%。
- 成交量容量：按最近 20 根 K 线的成交量和参与率限制手数。

通过的候选交给四种选择方式之一：

| 方式 | 含义 |
| --- | --- |
| BEST_EV | 选保守期望最高的 |
| PROBABILITY_SAMPLE | 90% 的权重按期望大小随机抽，10% 留给空仓，种子固定 |
| FIXED | 只用事先指定的一个策略（当前指定趋势跟随） |
| CASH | 永远空仓，作对照 |

已有持仓时不换策略，只做持有、加仓、减仓或平仓。

#### ⑤ 虚拟成交与账本

- 信号在 K 线收盘后产生，下一根 K 线开盘成交。止损和止盈同时在一根 K 线内触发时，按止损处理。
- 六种成本场景：基准、手续费翻倍、滑点翻倍、保证金乘 1.5、跳空、无法止损。
- 一个连续的账户，记录每笔成交、手续费、保证金、逐日权益。金额用十进制精确计算。

#### 滚动验证（M5）

`scripts/research_probability_v2.py --mode walk-forward`：按时间切成训练 252 个交易日、校准 60 日、测试 60 日，中间留隔离带；在测试段上回放四种选择方式和六种成本场景，输出指标、账户和清单。还有一次性的最终留出集，至今没有动用。

### 3.6 读这一节时需要知道的四件事

1. **v2 目前在真实数据上开不出仓，原因是代码缺陷，不是市场。** 上表里的两条“做不到”都已用探针复现。在它们修好之前，v2 的任何真实数据报告都会是零成交。
2. **v2 的门槛是按分钟线的样本量设计的。** “同一个 5% 概率区间内 200 个校准样本”在分钟线上一两天就够，在日线上 60 个校准日里每个合约最多 60 个样本。所以即使修好了缺陷，日线报告仍很可能因为样本不足而全部空仓，这不代表策略无效。详见 REVIEW 的 X03。
3. **v2 的风控参数隐含了最低资金。** 按示意参数估算，螺纹钢日线开 1 手需要权益约 11.7 万元，分钟线约 6.2 万元；铜、黄金、原油的日线在 100 万元以下开不了。计划里的 1.5 万、5 万、10 万三档，螺纹钢日线大概率一手都开不出。详见 REVIEW 的 X04，可用 `probes/budget_feasibility.py` 代入真实参数重算。
4. **v1 和 v2 的差别很大。** v1 是“有信号就按固定手数做”，简单、能立刻出结果，但没有样本外检验。v2 把同样的价格形态包在概率、证据、预算三层条件里，严谨得多，代价是慢，而且条件太严时可能一笔都不做。

## 四、策略以外的功能

### 数据

- 行情下载：合约级和主连的分钟线、日线回补脚本十余个（`scripts/backfill_*.py`、`fill_recent_main_minute.py` 等），含失败重试和看门狗。
- 会员持仓排名：每日采集多空持仓排名入库。
- 交易所规则：从六家交易所官网抓取手续费、保证金、交易时间的原文，保留原件和哈希，抽取候选值，经人工逐字段批准后才算“当前值”。带一个只读的本地网页工作台。
- 结算参数快照：每日保证金和手续费，与规则交叉核对。
- 新鲜度检查：只查指定样本，过期返回非零，不触发下载。
- 另有一套带监控、报表、看板的数据管线，但它在仓库里不完整（缺 6 个模块），从仓库克隆下来无法运行。详见 REVIEW 的 X21。

### 交易客户端接口

- **观察桥**：无限易客户端里的观察策略把行情和账户信息发到本机 17778 端口，服务只返回“持有”。任何打开交易开关的尝试都会被拦下。
- **执行域**：本机 17779 端口的执行服务加客户端里的执行策略。包含限价单规划、两阶段派发、SQLite 账本、对账，以及一套“配对 → 武装 → 限次发单”的授权流程。默认 `enable_trading=False`，真实报单数为 0。
- **TqSdk 模拟**：`run_sim_strategy.py` 等脚本可在本地模拟账户上跑演示策略。

### 其他

- 行情 MCP 服务：八个只读查询工具，带令牌、限流、IP 白名单和审计日志。
- 宏观新闻 MCP 的接入说明。
- 因子库：605 条因子定义的只读目录（定义，不是数值）。
- 证据校验、基准测试框架、离线测试入口（运行时拦截联网和数据库访问）。

## 五、现在可以直接用的命令

在仓库根目录，按 README 的写法：

```powershell
# 查数据库状态与某个合约的样本
python scripts/manage_database.py status
python scripts/query_market_data.py list --symbol SHFE.rb2101 --duration 86400 --start 2020-01-01T00:00:00+08:00 --end 2021-02-01T00:00:00+08:00 --limit 5

# 冻结一段行情
python scripts/export_futures_input.py --env-file .env --products SHFE.rb --start 2020-01-01T00:00:00+08:00 --end 2021-02-01T00:00:00+08:00 --duration 86400 --universe-cache data/downloads/backfill_contract_universe.json --catalog config/china_futures_catalog.json --output data/research_runs/rb-history-input

# 用 v1 策略做单合约日线回测（三选一：donchian_trend、ma_trend、zscore_reversion）
python scripts/backtest_history.py --input-bundle data/research_runs/rb-history-input --symbol SHFE.rb2101 --strategy ma_trend --config config/scenario_rb_example.json --output data/research_runs/rb2101-ma-scenario

# v1 概率研究
python scripts/research_probability_strategies.py --input-bundle <冻结包> --config config/probability_rb_example.json --output data/research_runs/probability-rb-first
```

v2 的入口 `scripts/research_probability_v2.py` 需要一份不在仓库里的“合同锁”文件，目前只能在你的本机工作区运行。
