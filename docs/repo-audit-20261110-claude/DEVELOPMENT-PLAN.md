## 一、总则

**并行**（沿用 G1）：关键路径同时一条开发线、一条独立审核线，另有一条支撑线。

**每个产品改动的固定流程**：

```
计划作者裁定（只在涉及语义时）
→ 开发：改代码、加测试
→ 自测：受影响的测试 + CI 同款选择
→ 全量跑一次，与基线比较（K03 之后）：新增失败为 0
→ 冻结，独立硬审（审核范围写明包含哪些测试文件）
→ 合入 main，CI 通过
→ 提交说明里写：命令、原始退出码、passed/failed 数、基线对照结果
```

**完成标准**：独立硬审 PASS、合入 main、CI 通过、全量失败清单无新增。最后一条是本轮建议新增的（J5），在你批准之前作为自查项执行。

**记录**（沿用 G4）：只更新 `docs/CURRENT-STATUS.md`；不为每一步新建过程文档；原始日志放仓库外。

**候选代码**：仓库转私有后，每条开发线每天把分支推到远端。
