## 需要你决定的流程调整

这六项都会改变项目规则，只有你能拍板；本地 agent 在你决定前不应自行修改 AGENTS.md。前四项对效率影响最大，建议本周定下来。

| 编号 | 决定事项 | 我的建议 | 理由 |
| --- | --- | --- | --- |
| F1 | 角色稳定期 | 开发路由保持 ZCode 至少到 11-30；之后若要更换，先写明原因和用什么指标评估 | 每次换路由都要停写、交接，并改五个规则文件，而且会留下过期文字（N5） |
| F2 | 并行上限 | 同时最多 3 条开发线加 1 条审核线 | 5 路并行时 502 频发，Root 的调度错误也集中在多路时；并行多了不等于交付多了 |
| F3 | 失败重试规则 | 一次工具都未调用时发生的 5xx、429 和连接中断，自动退避重试最多 3 次，只记一行日志；已经有写入后的失败才走人工处置 | 这类失败没有副作用，人工处置只增加记录和等待 |
| F4 | 证据存放 | 运行证据、容量账和会话记录移到独立的证据仓库或对象存储；主仓库只留代码、计划，以及每项接受的一页结论 | 主仓库已有 167 个 docs 文件，过程记录还在每天数千行地增长 |
| F5 | 事实来源 | 分支、PR 和 CI 作为唯一事实来源；接受结论引用提交号；逐文件冻结哈希只用于仓库外的输入 | 提交号本身就是内容寻址的快照，而且不受换行设置影响（N4） |
| F6 | 状态页 | PROJECT-STATUS.md 改为每周一页，只放下一节的指标；进程、PID、会话信息写进日志 | 现在的状态页回答不了“离可用还有多远” |

独立硬审核、交易安全边界和不读取凭据这三条不在调整范围内，建议保持现状。
