# 策略优先蓝图

**版本**：strategy-first-blueprint-20261015-r1  
**性质**：规划文件，供后续 Codex 计划、实现、独立复核使用。  
**适用范围**：RB-A/B-1 的首个策略交付和其模拟交易准备。  

## 1. 目标

首个交付目标是用同源 RB 输入完成 MINUTE+DAILY 双频的真实 M5 A/B。  
策略优先意味着先得到可复现、可审查的研究出口，再决定是否进入模拟交易。  
首批只推进 TREND、BREAKOUT、PULLBACK 三个策略族。  
其余入口保持 `NOT_RUN`、`BLOCKED` 或 `INSUFFICIENT`，不得用推测结果填充。  

交付要回答三个问题：数据是否可用于因果研究，策略是否通过规定的回测约束，研究出口是否能安全地供影子模拟消费。  
交付不承诺收益、胜率、上线日期或任何真实订单。  

## 2. 可信前提与当前边界

现有 RB causal、scenario、capital 检查的局部结果只能标为 `SCENARIO/CALENDAR_UNVERIFIED`。  
M5 full100 尚未运行，不能把局部 PASS 写成完整历史结论。  
M1 P1 的 required map 实际包含 42 项；旧测试仍断言 41 项，且缺少 `test_v2_m1_p1_open_contracts.py`。  
该测试状态记录为 184P/1F，属于待修复契约差异，不是策略失败证据。  
snapshot P2 人口 25679 在 300 秒限制内超时，观测到 elapsed 308.719 秒、peak 121106432；这是超时，不是 OOM。  
DAILY seam 流程状态为 `INCOMPLETE_NOT_ACCEPTED`，因此 DAILY 频率仍是交付依赖。  
R5 `experiments.py:603` 读取未定义的 `_reg`，checkpoint 还缺 `exit_registry_sha256` 与 `exit_bindings`。  
R5 修复只在真实消费者会使用这些绑定时前置，不能为了蓝图先行扩展范围。  
G3→G4→G6 必须按消费者绑定推进。  
APUB、EX06、通用 runtime、远端宏观、全品种和部署不构成本蓝图的通用门。  

## 3. 研究不变量

所有正式研究沿用 252/60/60 的时间划分。  
训练、验证和永久留出必须有明确日期边界，并由 PIT 数据规则约束。  
purge 与 embargo 的窗口由现有契约确定，实施时记录实际值和缺失值。  
永久留出只在规定的最终阶段读取，不能反复调参。  
成本模型和压力情景必须同时报告基线与压力结果。  
研究过程沿用连续账本，保留输入、参数、版本、结果和异常的可追溯关系。  
任何未知、缺失或未验证状态都转为空仓语义；未知不等于预测为零。  
合成输入必须标注 `SYNTHETIC`，日历缺口必须作为缺口记录，不能伪装成历史 PIT。  
不要求全量笛卡尔积；组合选择必须有理由并记录未覆盖组合的状态。  

## 4. 首批真实交付物

交付物一是 RB-A/B-1 的同源输入说明、MINUTE/DAILY 对齐结果、PIT 证明和 M5 A/B 数据包。  
交付物二是三个策略族的最小可比结果表，包含 252/60/60、purge/embargo、永久留出、成本和压力字段。  
交付物三是按连续账本关联的研究出口，能被后续影子模拟读取并保持未知即空仓。  
交付物四是研究出口的消费契约、版本绑定、异常处置和重放入口。  
交付物五是待审查的验证证据索引，以及可供独立 ZCode 硬审冻结的写集清单。  
交付物六是模拟交易前置包：研究出口、execution hard PASS 证明、20 交易日 feed/clock/shadow 记录和 send/cancel=0 计数。  

## 5. 模块边界与文件归属

RB 输入、频率拼接和日历缺口由数据节点负责；该节点只写其获授权的数据适配与契约测试文件。  
策略计算、参数候选、回测编排和结果表由策略节点负责；策略节点不修改数据节点的契约实现。  
研究出口、连续账本绑定和消费适配由研究出口节点负责；R5 的 `_reg` 修复只能由其文件所有者处理。  
模拟 feed、clock、shadow 计数和禁交易断言由模拟节点负责；它不承担真实 broker 连接。  
execution hard review 和部署边界由执行节点负责；其写集与策略节点分离。  
本蓝图及两个配套文件归项目文档节点负责，现阶段只允许写本目录三个文件。  
每个实现节点提交前记录其文件列表和 SHA-256；跨节点文件由 Codex 仲裁后才能变更。  

## 6. 依赖顺序

先冻结已有 contract lock 和 RB 输入边界，再完成 MINUTE+DAILY seam。  
seam 达到可接受状态后，才运行 M5 full100 和三个首批策略族。  
策略结果通过规定验证后，才生成研究出口并交给模拟消费者。  
研究出口消费通过 20 交易日 feed/clock/shadow 观察后，才进入执行域硬审结论的联合验收。  
所有阶段都保留 `NOT_RUN`、`BLOCKED`、`INSUFFICIENT` 的真实状态。  
未满足依赖时停止推进对应阶段，但继续推进不依赖它的准备性工作。  

## 7. 模拟交易边界

默认 `enable_trading=False`，observer 模式永远回答 `hold`。  
模拟 acceptance 必须同时具备研究出口、execution hard PASS、20 交易日 feed/clock/shadow 和真实 send/cancel=0。  
最后还需要用户明确授权并在客户端 UI 开启交易；计划文件本身不提供该授权。  
在上述条件满足前，broker 记录保持 `NOT_RUN`，不得触发真实下单或撤单。  

## 8. 验收与停止条件

策略首批验收要求三类策略均有可重放输入、完整状态字段和独立验证证据。  
M5 full100、DAILY seam、PIT、purge/embargo、永久留出、成本压力和连续账本缺一项，整体只能标为未完成。  
旧测试的 41/42 契约差异必须由所属节点修复或形成明确的 `BLOCKED` 证据。  
超时必须保留原始 elapsed、资源观测和命令结果，不能改称 OOM 或成功。  
任何未定义变量、缺失 checkpoint 绑定或消费者不匹配都停止研究出口发布。  
独立 ZCode 硬审必须针对冻结后的实际写集给出 PASS；计划、开发者自测和证据整理都不等于硬审。  
硬审 FAIL 时回到原实现所有者做追加修复，并以新的冻结哈希重新复核。  
本蓝图只描述工作范围和门槛，不是实现授权，不是交易授权，也不是 ZCode PASS。  
不新增封存体系，不臆造时间或收益，不把未跑的组合写成已完成。
