# 第八轮外部审核（2026-11-14）

审核对象：`main` 的 `0cce743`（第四批收尾）。这是外部审核意见和替用户登记的决定，不是产品硬审核。本目录只新增文档和只读探针，不改产品代码、测试和规则文件。

## 一段话结论

第四批的说法全部属实：第二版六品种报告（K46）交付并通过独立硬审，我用已入库的文件做了 39,644 项核对，没有不一致；全量测试原有的 6,056 项逐项没有变化，新增的 79 项全部通过。六个品种合在一起，突破规则六年 +21%，但 95% 区间是 −16% 到 +61%，和运气分不开，三个日线规则到此收尾。预测检验（K45）停在了开工之前，停下的原因不在检验本身，而在阶段之间“把每条记录完整写出再读回”：每个决策时刻要展开 16 份全部历史分钟线的清单，全程 1.5 万亿字节。把对象直接留在内存里、阶段之间只核对编号，整条链在我的机器上约一个半小时能跑完，折算到本地机器约半天。所以第五批只做一件事：K45 再做一次，检验的内容不改，只改在机器上怎么跑。

## 探针

都是只读的，只用标准库和仓库里的生产函数，用合成数据或已入库的文件。在仓库根目录运行。

| 探针 | 回答什么问题 | 我这边的结果 |
| --- | --- | --- |
| `k46_published_tables_recheck.py` | 第二版报告的表格之间、表格与正文之间对不对得上；合并口径的 +21% 和运气分不分得开 | 退出码 0；39,644 项，不一致 0 项；约 2 秒 |
| `k45_inmemory_stage_cost_probe.py` | K45 每个决策时刻各步在内存里做要多久；展开写出再读回要多久；行情参照走两个入口各要多久；另一个进程重算出的编号是否相同 | 退出码 1（问题存在）；最长历史上展开往返是内存里全部步骤的 11.5 倍；编号序列相同；约 50 秒 |
| `k45_end_to_end_in_memory_probe.py` | 整条链在内存里从特征到评分能不能跑通，各步占多少时间，占多少内存 | 退出码 0；4,921 个决策时刻，498 秒，内存峰值约 2.8 GB |

python -B -X utf8 docs/repo-audit-20261114-r8-claude/probes/k46_published_tables_recheck.py
